# Automatic native BC format selection

For the complete native statistics and validated MILP/local-search/3-D Pareto
workflow, see [NativeMixedPrecisionPipeline.md](NativeMixedPrecisionPipeline.md).
This entry uses the two-dimensional knee policy described below by default;
`--policy 3d` switches to local size/BOPs probes, a 3-D Pareto set, and the
anchor-normalized ideal-distance pick (not the default: on Qwen3-0.6B it chose
int4 weights everywhere, PPL 108 vs FP32 49.9, see section 12.1 of that document).

Run from the repository root:

```bash
venv/bin/python experiments/mixed_precision/run_native_auto.py \
  --models mobilenetv2 --out-dir /tmp/my-native-auto
```

No weight-size or BOPs budget is required. Available model/data adapters are
`mobilenetv2`, `resnet18`, `efficientnet_b0`, `gpt2`, `bert`, and `qwen3`, using the
same local assets as `run_native_bc_pipeline.py` (`qwen3` needs `qwen3_prepare.py`
run first). Multiple names can be comma-separated.
The output directory must be new or empty. By default CNNs use 1,000 held-out
images; `--num-eval` changes reporting sample count, never selection. GPT-2 uses
and Qwen3 their 32 test windows, and BERT its 872 validation sentences.
`--eval-chunks N` splits each held-out evaluation over N processes (every input
still runs alone through the same library, so results do not change), and the
FP32 model is compiled and evaluated the same way as a baseline unless
`--no-fp32-baseline` is given. `--time-limit` bounds each MILP solve (10 s).

The pipeline builds native range, gradient, and quantization-error statistics,
constructs B(w)+C(a), selects a configuration, compiles it, and evaluates it.
The candidate set includes int4–int8, p4e1/p6e1/p8e1, f16, bf16, and fp32.
Integer weights use per-output-channel quantization. Selection applies to the
same weight-bearing nodes as the corresponding existing experiment; other
nodes keep their existing FP32 behavior. The old fixed-budget driver remains
available for controlled experiments.

## What replaces a manually chosen budget

The default policy is a **normalized chord knee on predicted BC cost**:

1. Define resource as the larger of weight-bytes/int8-bytes and BOPs/int8-BOPs.
   This preserves the earlier experiments' convention of bounding both ratios
   by one factor. Both resource quantities cover the selected nodes only.
2. Derive a lower resource bound from the allowed candidate formats. Construct
   cheap and minimum-BC endpoint assignments to derive a feasible upper bound.
   Nonfinite costs are forbidden; negative BC costs are rejected.
3. Solve MILP at 17 logarithmically spaced internal budgets, then refine around
   the knee twice with up to three additional solves per refinement. These
   budgets are generated by the program, not supplied by the user.
4. Remove sampled points dominated in resource and BC error. Normalize both
   axes between the endpoint values, and choose the point furthest below the
   line joining the endpoints. Exact score ties prefer lower predicted error.
   A flat cost curve chooses the cheapest point. A straight declining curve
   has no interior knee and falls back to the high-quality endpoint.
5. Freeze the selected formats, compile `selected.so`, and only then evaluate
   held-out inputs. Evaluation metrics never select or refine the configuration.

This is a deterministic default tradeoff heuristic, not a unique mathematical
best operating point. It searches a sampled two-objective frontier, not every
point of the three-objective size/BOPs/error frontier. The BC surrogate does
not guarantee a particular accuracy or perplexity degradation. Applications
requiring such a guarantee need a separate quality-constrained selection
policy and a tuning split distinct from the final test split.

MILP has a 60-second limit per solve. `solver_status=0` means optimal for that
internal budget; `1` is an incumbent without an optimality proof. Status and
failed solves are retained in the search report. Analytical minimum-BC
endpoints are identified by `origin`. Selection itself is a knee heuristic
even when all constituent MILP solves are optimal.

## Outputs

Under each model directory:

- `selection.json`: policy, inferred bounds, attempted budgets, solver statuses,
  candidate configurations, sampled frontier, knee scores, and chosen point.
- `selected_formats.json`: final per-node weight/activation formats.
- `compile_env.json`: exact mixed-precision pass configuration, including INT
  activation scale/zero-point parameters and per-channel weight mode.
- `selected/`: reusable compiled model (`selected.so` with its
  `model.constants.bin`) and `per_item.npy`, the per-item held-out losses;
  `fp32/` the same for the FP32 baseline. Logits are not kept (GBs for the
  language models).
- `results.json`: selected configuration, held-out metrics, FP32 baseline
  metrics and the paired per-item loss difference, timings, artifact path, and
  explicit flags that evaluation did not select the model and that no accuracy
  guarantee is claimed.
- Native tables, layouts, and intermediate IR are retained for inspection.

The auto entry does not compute the offline PyTorch reference table and does
not require saved old BC/SQNR results. The driver and MILP still run in Python;
native refers to ONNX-MLIR-generated statistic and inference graphs. As in the
existing mixed-precision experiments, formats are simulated via QDQ around
FP32 operations. Resource ratios are estimates, not measured file sizes,
latency, energy, or proof of native low-bit hardware execution.

Validation:

```bash
venv/bin/python -m unittest discover -s test/mixed_precision \
  -p test_mixed_precision_auto.py -v
```
