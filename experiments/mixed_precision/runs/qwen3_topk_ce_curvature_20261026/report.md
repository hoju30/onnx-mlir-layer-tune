# Qwen3-0.6B L27 Down：低成本 top-256 CE 二次項能否修正候選排序？

日期：2026-10-26。
- 腳本：`run_qwen3_topk_ce_curvature.py`。
- 計畫：`plan.json`／`plan.md`（23:06:06 寫入，沒有 amendment）。
- 規格：`reports/qwen3_topk_ce_curvature_prompt_20261026.md`。

**範圍**
- 只做 L27 Down；目標權重在所有條件都固定為 A 的 INT8。
- 背景 U／F／W、九種格式（完整 input／output QDQ）、batch 8 與尾批的 GEMM 形狀，都與前兩輪相同。
- 只用 GPU LMReplay。
- 沒有修改正式 BC、量化器、配置、MILP／knee 或 native。

**主方法**：固定 k = 256，在計畫中預先定下，看到結果後沒有更換。

**定義**（逐窗口、逐預測位置計算）
- 機率 p：baseline f16 的完整機率，來自梯度那次 microbatch-1 forward 的 FP32 logits，以 float64 做 softmax。
- T_256：依 p 取前 256 個詞，平手取 token id 較小者。
- q：tail 機率，直接加總，不重新正規化。
- 近似：

  ```
  Khat_256 = ½[Σ_T p_v (W_v·du − m)² + q (a_tail − m)²]
  P256     = S_u + Khat_256
  ```

  - q·a_tail = w_tail·du，其中 w_tail = W^T(p·1_tail)，在 baseline 時用一次 FP32 GEMM 算出。
  - m = Σ_T p a + q a_tail，與 (W^T p)·du 相同。
  - q ≤ 1e-12 時 tail 項為 0。本輪 q 的最小值是 8.5e-10，這個分支沒有被觸發。
- k = 1024 只在 C 上作診斷，不進入新文章的選擇器。

**資料與單位**
- C：原 10 個 calibration 窗口，只用來建立分數並凍結選擇器。
- N：全新的 128 篇文章 × 2 窗口，只量真值。
- 數值是相對同背景 f16 的 nat/token 貢獻，負值代表有利。
- N 的區間是文章 bootstrap 20000 次的 95% CI（seed 26102683）。

## 首頁

### 1. top-256 補回了 INT8、Posit6、Posit4 漏掉的代價

F 背景、C、全部位置（三個背景結果相同，見後文）：

| 格式 | S_u | Khat256 | K2（精確，affine = actual） | KL | **P256** | **D（真值）** | D − P256 | 漏掉的 tail 方差 | KL − K2 |
|---|---|---|---|---|---|---|---|---|---|
| p8e1 | −0.0162 | +0.0087 | +0.0114 | +0.0117 | **−0.0075** | −0.0045 | +0.0029 | +0.0027 | +0.0002 |
| p6e1 | −0.0353 | +0.1049 | +0.1184 | +0.1151 | **+0.0695** | +0.0797 | +0.0102 | +0.0135 | −0.0033 |
| p4e1 | +0.0201 | +0.2203 | +0.2499 | +0.2313 | **+0.2405** | +0.2514 | +0.0109 | +0.0296 | −0.0186 |
| int8 | −0.1623 | +0.6404 | +0.6635 | +0.5400 | **+0.4781** | +0.3778 | −0.1004 | +0.0231 | −0.1235 |

**方向與排序都修好了**
- 相對 f16 的好壞方向，三個背景都是 8/8 個非 f16 格式正確。原本 S_u 是 7／6／6。
- 選擇集合內 28 對的順序，三個背景都是 28/28，與 C 真值完全一致。原本 S_u 是 22／19／19。
- 同位元的 INT／Posit 三對全部正確，int8–p8e1 也由錯轉對。

**剩下的誤差分成三類**（C，F 背景）

| 誤差來源 | 大小 | 說明 |
|---|---|---|
| tail 方差遺漏（K2_affine − Khat256） | 對 Posit 是 +0.003～+0.030 | 使 P256 略為低估 Posit 的傷害 |
| 二次近似餘項（KL − K2_actual） | 對 INT 是 −0.12 | 二次項高估大擾動的 KL，使 P256 高估 INT 的傷害（偏安全） |
| 數值差（K2_actual − K2_affine） | 每 token ≤ 4e-7 | 可以忽略；microbatch-1 與 batch-8 的 baseline logits 逐位元相同 |

- 這三項沒有一項大到改變排序。

**tail 方差集中在 position 0**
- k = 256 時，P0 的 tail mass 平均 0.57–0.75，Rest 平均只有 0.065（中位數 0.024）。
- 例如 F 背景 p8e1 的 tail 遺漏是 0.0027，其中 0.0023 在 P0。
- 因此 P256 對 p8e1 的有利程度估得過頭：−0.0075，真值 −0.0045。

**k = 1024**（只在 C 上診斷）
- 遺漏變小：F 背景 p8e1 為 +0.0016，p4e1 為 +0.0155。排序與 k = 256 相同，margin 略小。
- 只是診斷，不能用來替換主方法。

### 3. 省時：比完整 K2 省 44%，比直接 CE 只省 18%

測量條件：F 背景、C 的 10 個窗口、7 個非 f16 候選（f16 在各方法都重用 baseline）；5 次 warmup + 20 次計時，取 median（p90 與 median 差 < 0.3%）；RTX 3060。

| 方法 | baseline（只算一次） | 候選熱增量（7 個） | **總計（prefix 已備）** | 峰值 VRAM 增量 |
|---|---|---|---|---|
| Su（不含 CE 代價） | 0.128 s | 0.023 s | 0.150 s | 0.33 GB |
| **Su + Khat256** | 0.427 s | **0.029 s** | **0.456 s** | 1.81 GB（W_T 快取 1.33 GB） |
| Su + 完整 K2（FP32 GEMM） | 0.246 s | 0.566 s | 0.815 s | 2.45 GB |
| 直接候選 head + CE（精確真值） | 0.067 s | 0.491 s | 0.558 s | 1.90 GB |

**候選熱增量**
- 每個候選約 4 ms，完整 K2 約 81 ms、直接 CE 約 70 ms，便宜 17–19 倍。

**Khat256 的 baseline 前處理**（10 個窗口，合計 0.30 s）

| 子步驟 | 時間 |
|---|---|
| float64 softmax | 0.110 s |
| top-k 與平手處理 | 0.098 s |
| w_tail dense GEMM | 0.078 s |
| index、p_T、q | 0.032 s |
| W_T row gather | 0.011 s |

- 這部分吃掉大部分節省：在 7 個候選時，總計只比直接 CE 快 18%，比完整 K2 快 44%。
- 按每候選的增量推算，損益平衡點約為：對直接 CE 5.5 個候選，對完整 K2 2.4 個候選。

**冷啟動**（C 全流程）

| 項目 | 時間 |
|---|---|
| replay 初始化 | 6.6 s |
| F 背景量化 | 8.0 s |
| 第一次 prefix | 1.1 s |
| 各方法第一次執行 | 0.16／0.51／0.81／0.55 s |

- 冷啟動合計約 16 s，主要由準備工作決定，四種方法差不到 0.7 s。

**計時實作與凍結值一致**
- S_u 差 3e-17，Khat256 差 1e-16。
- FP32 完整 K2 與 float64 歸約的 K2_affine 差 1.2e-7。
- 直接 CE 與真值 D 差 7e-10。

**限制**
- L27 後面只有 norm 與 head，是特例；在這裡，直接算候選 CE 本身就是精確又不貴的做法。
- 這些成本不能外推到其他層、全模型 offline 時間或 native。

### 4. 下一步

**支持的結論**（L27、GPU）
- 在固定的 k = 256 下，S_u + Khat256 在 C 上完全排對。
- 凍結後在新文章上選到 p8e1，確認比 f16 好，也避開了 S_u 的嚴重錯誤（INT8 +0.38）。

**最小的下一步**（待驗，本輪未執行）
1. **跨層可行性**：其他層後面還有 QDQ 與多層非線性，「head 的二次項」不能直接搬過去。需要先設計如何得到該層輸出空間的 CE 曲率（例如以 L27 的形式為上界，或下一層的 Fisher），並在一個非最後層上做相同的預登記驗證。
2. **省時**：大部分 baseline 成本在 float64 softmax、top-k 與 w_tail GEMM。若改用 FP32 softmax，或重用 g_u + W_y 取得 w̄（本輪 float64 控制顯示差 2.4e-5），可以再省，但要另輪預先登記並驗證數值。
3. **與原 BC 的關係**：原 BC 有自己的類二階項。本輪沒有證明 BC 少了一個可以直接相加的 K2，不應混用。

**需要保留的判讀**
- 在 L27，直接 CE 只慢 18%，而且是精確值；所以「低成本近似」在 L27 的實用價值有限。它的意義在於：如果之後要推廣到後綴更長、直接 CE 很貴的層，這個 signed 一階加 CE 二次的結構，是值得驗證的候選。

## 控制（全部通過）

**合成小詞彙表（float64）**
- 誤差都 ≤ 1e-15，項目包括：
  - k = V 時回到完整 Fisher 方差（tail mass 0）；
  - q < 1e-12 的分支；
  - 共同 logit shift 不改變 K；
  - tail 恆等式與巢狀關係；
  - 平手規則取較小 token id。

**LM head 與 final norm**
- LM head 是無 bias 的 `Linear`，與 embedding 共享權重，不在搜尋與量化之列，沒有 hook，沒有 softcap 或 temperature。
- final norm 是 Qwen3RMSNorm，eps 1e-6。

**與前輪及完整 forward 的一致性**
- closure = 完整 forward（3 背景 × 9 格式，差 0）。
- 重現前輪 C 逐位置的 D、S_z、S_u、KL、K2：差 0。
- S_u 選擇器重現 int8。

**梯度與位置**
- 梯度鏈：VJP 相對差 0；與解析 Jacobian 的相對差 1.8e-7。
- 位置 127 的 g 與 S 都為 0。Khat 只在 127 個 target 位置計算。

**top-k 與 Khat 的數值**

| 檢查 | 結果 |
|---|---|
| 每位置剛好選 k 個詞 | 是 |
| T_256 ⊂ T_1024 | 是 |
| 巢狀 Khat256 ≤ Khat1024 ≤ K2_affine（容差 1e-9 + 1e-4·K2，沒有任何違反） | 最大原始差：Khat1024 − K2_affine = +1.7e-7（FP32 GEMM 差異，在容差內） |
| K2_affine − Khat = ½q·Var_tail 恆等式 | 最大誤差 9e-15 |
| 便宜實作與「從完整 a 算的 Khat」 | 最大絕對差 2.1e-5（大 K 位置，相對 < 1e-4） |
| float64 參考（F 背景，窗口 0 與 9，全部位置與格式） | FP32 實作最大絕對差 2.0e-5，在容差內 |
| 隱含 w̄ 與 float64 W^T p | 相對差 6.8e-7 |
| g_u + W_y 與 W^T p（只報告，沒有使用） | 相對差 2.4e-5 |
| microbatch-1 與 batch-8 的 baseline logits | 逐位元相同 |

**其他**
- f16 的 du、S、所有 K 與 D 都精確為 0；fp32 沒有強迫為 0。
- P0 + Rest = All：誤差 4.5e-13。
- 三個背景的目標權重都是 INT8；TF32 關閉、deterministic。
- N：f16 closure 與完整 forward 的差為 0。
