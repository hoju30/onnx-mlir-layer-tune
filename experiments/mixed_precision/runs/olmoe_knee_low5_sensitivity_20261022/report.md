## 回答五個問題

**1. D5 是否優於原始 BC？**
- **沒有確認。** 點估計幾乎為 0（+0.000008）。
- 校正區間能排除的：改善超過 0.00082，或變差超過 0.00084。本批 B 的收益是 −0.00084，剛好落在區間之外。
- 不能排除的：最多約 0.0008 nat/token 的小改善（約為損傷的 5%）。

**2. D5 是否優於 D4，支持擴大更新範圍？**
- **沒有確認。** D5 − D4 = −0.00011，校正 CI [−0.00090, +0.00068]。
- 不能排除 D5 比 D4 好約 0.0009，也不能排除差約 0.0007。
- 本批的 D4 − A 也是 +0.00012（未確認）；兩者相對 static 都沒有收益。

**3. D5 是否保留 B 的品質？節省多少時間？**
- **品質**：
  - 非劣沒有成立（校正上界 +0.00163 > +0.0005）。
  - 校正區間排除了「D5 和 B 一樣好或更好」。
  - 但不能排除 D5 只比 B 差約 0.0001，也不能排除差到 0.0016。
- **時間**（已有快取與 q0_knee 時的額外更新＋搜尋，3 次中位數）：
  - D5 45.9 秒、B 80.0 秒，**少 34.1 秒（−43%）**。
  - 節省來自：weight sensitivity 26.4 → 11.0 秒、activation 誤差 12.3 → 0 秒（改讀快取）、ΔW 讀取 11.3 → 5.9 秒、梯度統計 3.2 → 1.6 秒。
  - D5 的目標雖然佔投影數的 50%，但在 q0_knee calibration 只拿到 44.8% 的 routed rows（73,331／163,838），所以 weight sensitivity 降到 B 的 42%。

**4. 相對 C，只選約一半投影的效益如何？**
- **時間**：D5 45.9 秒、C 68.5 秒，少 22.6 秒（−33%）。
- **品質**：D5 − C = +0.00039，95% CI [−0.00027, +0.00106]，未確認。
- 但本批的 C − A（−0.00039）也沒有確認，所以**沒有一個確認過的收益可以讓 D5 去保留**。
- 配置面（描述性）：
  - D5 對 A 改了 134 個投影：在原 ≤4-bit 集合 32 個、新增的 5-bit 集合 94 個、其餘 8 個。
  - C 對 A 改了 198 個：33／107／58。B 改了 201 個：33／108／60。
  - 換句話說，D5 和 C 在 5-bit 集合內做了數量相近的改動；主要差別是 D5 幾乎不動 ≥6-bit 的節點。這些差別對 loss 的影響，本批無法解析。

**5. 是否值得保留為可選步驟？**
- **不值得。** D5 對 A 沒有收益，對 D4 沒有確認的優勢，也沒有證明保留 B 的品質。
- **[推論] 三批 knee 資料的整體圖像**（各批單獨配對，不合併、不跨批相減）：
  - 完整 refresh B 相對 A，三批的點估計都是負的；
  - 只更新 sensitivity 的 C、D4、D5 相對 A 都沒有確認。
  - 如果 knee 上有可用的 refresh 收益，它比較可能需要 activation error 的刷新，而不是靠調整 sensitivity 的更新範圍取得。這只是跨批的定性觀察，沒有經過預先登記的檢定。
- 結論只適用於本模型、本 knee、本 calibration 和 GPU QDQ。即使 D5 成功，也不能說 5-bit 是跨模型的最佳門檻；它沒有成功，也不代表其他選擇規則一定無效。依指示，本輪不接著測 ≤6-bit。

## D5 的定義（`plan.json`、`low5_nodes.json`）

**目標集合**：從凍結的 A 重算並凍結，FORMAT_BITS[w] ≤ 5 或 FORMAT_BITS[a] ≤ 5。
- 共 1512 個：169 個 int4 weight 加 1343 個 int5 weight；activation ≤5-bit 的 10 個投影都已包含在內。
- 和預期相同：D4 是 D5 的子集合，D5 之外有 1539 個投影。
- 依投影：gate 582、up 492、down 438；分布在 595 個 expert。
- 新增的 5-bit 集合有 1343 個投影、554 個 expert。

**更新方式**
- 目標投影：用同一次 q0_knee calibration forward 和 backward，更新 weight 和 activation sensitivity，重算全部候選格式的成本。
  - forward 使用 q0_knee 自己的 dynamic route；backward 把記錄的路由當成常數、activation QDQ 經 identity STE、gate／up 共用輸入使用 total gradient。
  - 誤差統計沿用 static 快取（明確傳入），activation 以 static routed rows 正規化。
- 非目標投影：逐位元沿用 static 表。
- 搜尋：在 knee 的精確上限下重新搜尋一次，所有投影都可以改格式；沒有第二次 refresh。

**計時的公平性**：D5 使用 `run_olmoe_knee_selective_sensitivity.build` 並傳入 targets。它只對目標投影保留梯度、計算統計，但反傳時仍經過所有 expert；不是先算完 C 的統計再遮罩。
