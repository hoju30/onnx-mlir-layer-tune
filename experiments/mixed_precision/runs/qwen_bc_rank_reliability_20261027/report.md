# 原 BC 排名可靠性實驗：Qwen3-0.6B

日期：2026-10-27（Asia/Taipei）。程式：[run_qwen_bc_rank_reliability.py](../../run_qwen_bc_rank_reliability.py)。

**結論：在這三個事先指定的 Down 層、FP32 背景下，原 BC 的同 bit 排名穩定且表現良好。這輪沒有支持加入「排名信心門檻」，也沒有提供必須修改 BC 或補一階項的新證據。**

- 主要比較：3 層 × 3 組校準 × 3 種 bit，共 27 個 INT／Posit 排名。每個排名在 5,000 次文章重抽樣中都不翻轉；依預先登記的 paired bootstrap CI 規則，新文章上 **27 對、0 錯、0 未定**。
- 27 個判讀共用 **9 個不同的層／格式對真值**，不是 27 次獨立成功。L15 的 8-bit 結果接近邊界；附報的 sign-flip 檢定 p = 0.05030，未達 0.05，其餘 8 對的 Holm-adjusted p = 0.000450。
- 全部格式配對：252 個判讀中 **219 對、3 錯、30 未定**。3 個錯誤都是同一件事：L7 的 FP16／BF16，在三組校準中重複出現；實測差僅 **0.00001696 nat/token**。
- 只有 5 個判讀低於預定的 95% 穩定門檻，其中 2 個實際排對、3 個真值未定，沒有被確認排錯的案例。因此這輪不能證明「不穩定就不可靠」，也不能證明穩定就一定正確。
- 本輪是 **native BC 建表＋GPU FP32/QDQ 損傷量測**，沒有跑完整混合精度配置，也沒有驗證 L26／L27、量化權重、已量化背景或 MoE。

**這輪在問什麼**

前一輪加入一階項的跨層實驗，校準集上的改善沒有轉移到新文章。但它比較的是輸出端 K 與 S+K，不能直接推論原 BC 有相同問題。本輪回到原 BC：如果反覆重抽校準文章，候選排名是否會變？排名不變時，是否仍可能排錯？

判斷依據是候選間的排序，不要求 BC 的絕對數值等於 ΔNLL。沒有把 BC 值和 NLL 值直接相減，也沒有由新文章結果調整分數或門檻。

**BC 與重抽樣方式**

本輪所有權重 FP32，所以只比較原 BC 的 activation 項 C。對一個 slot/channel，令 n 為校準窗口數乘上 128：

\[
\mu=\frac{S_1}{n},\qquad
C=\sum_{\text{slot,channel}}\left[
\frac{G_2}{n}\left(S_2-n\mu^2\right)+G_{\Sigma^2}\mu^2
\right].
\]

- G₂：跨樣本、跨位置的 g² 總和。
- GΣ²：先對每個樣本的梯度跨位置求和、平方，再跨樣本加總。
- S₁／S₂：量化誤差及量化誤差平方的總和。
- input 與 output 各自計算再相加，保留原實作；沒有加入 signed 一階項或新的 interaction 項。

保留每篇的 native 原始統計。每組進行 5,000 次有放回的文章重抽樣，每次重新聚合上述統計並重新算 μ、變異項與平均項。**不是直接平均各篇的 BC 分數**。重複文章的乘數聚合與顯式複製樣本結果一致。

穩定性 = 重抽樣後仍保留原排名的比例；≥95% 只用來分組描述。它不是「排對的機率」。即使是 100%，也只表示這 5,000 次抽樣沒有翻轉。

N 的真值使用 20,000 次配對文章 bootstrap，每篇先平均兩個窗口與各 127 個預測位置。95% CI 排除 0 才判方向；跨 0 記為未定，不能當作相等。九個同 bit 真值另報 sign-flip p 與 Holm 調整，其餘配對 CI 為探索性結果。

**全部格式配對：有沒有穩定地排錯？**

| BC 穩定性 | N 排對 | N 排錯 | N 真值未定 | 合計 |
|---|---:|---:|---:|---:|
| ≥95% | 217 | 3 | 27 | 247 |
| <95% | 2 | 0 | 3 | 5 |
| 合計 | 219 | 3 | 30 | 252 |

三組校準在 84 個不同的層／格式對中，有 **83 個排名一致**。不能把上表每個判讀當成獨立樣本，或拿這個成功比例推論所有模型／配置。

穩定誤排只有 **L7 FP16–BF16**：BC 三組都選 FP16，穩定性都是 100%；新文章 BF16 比 FP16 的 NLL 低 **0.00001696**，CI 為 **[0.00000170, 0.00003240]**（以 FP16−BF16 表示）。

這證明「穩定不保證正確」在本輪仍有例外，但效果非常小，且是探索性、多配對檢查的一個結果。沒有完成候選的 native/GPU 一致性驗證，尤其不能把這個微小差異直接解釋成需要加入一階項，或值得修改正式 pipeline。

低穩定性集中在兩個格式對：

| 層／比較 | 三組 BC 選擇 | 三組穩定性 | N 結果 |
|---|---|---|---|
| L7 Posit4–INT6 | 全選 Posit4 | 77.88%、95.82%、61.78% | Posit4 較好，差 −0.051181，CI [−0.057529, −0.044987] |
| L23 Posit6–INT8 | INT8、INT8、Posit6 | 62.38%、64.02%、81.06% | 未定，差 +0.001348，CI [−0.000504, +0.003210] |

因此以穩定性門檻淘汰／重測候選，這輪會攔下至少兩個已排對的判讀，卻攔不到唯一的穩定誤排。沒有證據支持直接加入這項規則；也不以這批 N 調整門檻。

**校準實測與新文章是否一致？**

BC 在 C 的同 bit 判讀為 25 對、2 錯；這兩個與 C 實測不同的選擇，在 N 都與 BC 同方向：

| 條件 | C 的 Posit−INT NLL | N 的 Posit−INT NLL | 說明 |
|---|---:|---:|---|
| L15、校準組 0、8-bit | +0.000394 | −0.000597 | C 選 INT8，N 主規則偏向 Posit8，但 N 證據較弱 |
| L15、校準組 2、6-bit | +0.004065 | −0.006475 | C 選 INT6，N 明確偏向 Posit6 |

全部格式配對在 C 為 219 對、33 錯。33 個 C 錯誤到了 N，有 15 個轉為 BC 排對、17 個未定、1 個仍錯；原本 C 排對的判讀中也有 2 個到了 N 排錯。這支持「不能只用少量校準文章的實測排序決定修改方向」，不等於所有既有誤排都來自校準抽樣。

每個分數的變異／平均項已保存於 `scores_C.csv`。本輪平均項占總 BC 的範圍：L7 約 0.051%–17.824%、L15 約 0.195%–17.187%、L23 約 0.132%–8.410%。這只是分數組成，不是變異項或平均項造成誤排的因果證據。

**研究決策與後續**

1. **保留原 BC，不因這輪改 criterion、加入一階、增加校準量或部署穩定性門檻。** 同 bit 主結果良好，唯一明確的探索性穩定誤排效應很小。
2. **不把這輪寫成「BC 全部問題已解決」。** 目標權重全部 FP32；前一輪目標權重 INT6、U/F 兩種背景，兩者條件不同。本輪沒有測已量化前層造成的排名漂移、input/output 聯合誤差的來源，或節點成本相加後完整配置的可靠性。
3. 若續做，優先針對**實際搜尋中會競爭的跨 bit 候選，以及既有量化配置下的排序轉移**，沿用歷史診斷而非重做一般同 bit 比較。先預登記具體配置／候選與實際選擇後果，用新窗口確認偏差是否足以改變配置品質，再決定是否值得重新評分。這是下一輪建議，本輪沒有執行或證明收益。
4. L7 的 FP16／BF16 微小逆序不應成為目前主要優化目標；若要作機制結論，至少需要候選跨後端確認與新文章重現，不能用本輪結果挑選修正式後再測同一批 N。
