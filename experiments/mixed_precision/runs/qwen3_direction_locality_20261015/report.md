# Qwen3-0.6B：平方 proxy 的方向與抵消、完整量化是否超出局部近似

日期：2026-10-15　腳本：`experiments/mixed_precision/run_qwen_direction_locality.py`　資料：`runs/qwen3_block_criterion_20261014` 的候選、量化器、cache 與逐窗口 loss（PyTorch 模擬；native 一致性已在該研究核對）

**這是事後分析**：calibration 與 tuning 窗口都已在前面的研究中分析過。預測量與門檻在執行前凍結於 `plan.json`。「a2 + calibration 一階」與錯誤歸因是看到結果後才加的診斷，下文會標明。


> **更正（2026-10-15，見 `runs/qwen3_curvature_transfer_20261015`）**：本報告的「精確局部模型」a1、a2 來自 h = 1/8 的對稱差分。
> - 在 sink 相關的案例（如 L0 Up、L2 Gate、L2 Up），它是 1/8 尺度的平均曲率，不是無限小的 Taylor 二階項：float64 檢查顯示，原點的 HVP 曲率為負，h ≤ 1/128 時有限差分才收斂到它。
> - 本報告的歸因（非局部、方向、二階近似）仍然成立，但「局部」應理解為「1/8 尺度」。

## 結論

**兩個假說都成立，但都不足以單獨說明現行 criterion（BC）的錯誤。** 以 activation-only 的 140 個候選、2084 個 tuning 配對來看：

| 排序依據 | 排對的配對 | 和上一列的差 | 代表的因素 |
|---|---:|---:|---|
| 實際 loss | 2084 | — | — |
| 精確局部模型 a1 + a2（tuning 窗口自己的） | 2000 | −84 | **超出局部範圍**（假說 2） |
| 只用局部二階項 a2（沒有方向） | 1833 | −167 | **缺少方向**（假說 1） |
| 現行 BC | 1780 | −53 | **二階項的近似**（Fisher、乘積分解） |

**BC 排錯的 304 對逐對歸因**：非局部 70（23%）、方向 137（45%）、二階近似 97（32%）。

1. **假說 1（平方 proxy 不表達方向與抵消）：描述上成立，但方向大多是評估窗口的雜訊，從 calibration 學不到。**
   - **BC 量的其實是損傷大小。** 對 Σ|ΔL| 的組內 Spearman 是 0.879，對帶號 S 只有 0.717。
   - **抵消很大，集中在非 int4 格式**：
     - 窗口之間：非 int4 候選的 |S| ÷ Σ|ΔL| 中位數是 0.42，int4 是 1.00；24% 候選的總 loss 反而下降。
     - 窗口內：一階項 ⟨gY, e⟩ 在位置 × channel 之間抵消 99.4%（|F|/Σ|g·e| 中位數 0.006）。
   - **方向貢獻集中在不含 int4 的配對**（135/137）。
   - **方向無法從 calibration 取得。**
     - 把局部模型的一階項換成 calibration 估的（a2 + F_cal，事後加入）：1831 對，等於只用 a2 的 1833。
     - 依 Taylor、不調係數的 F_cal + ½BC：1773 對，略低於 BC 的 1780。
     - calibration 與 tuning 一階項的排序相關只有 0.65–0.80，正負號一致 66–78%。
     - 例外是 weight-only 組：加入帶號項後 Spearman 從 0.449 升到 0.554（+34 對）。那裡的方向有部分系統性。
2. **假說 2（完整量化超出局部近似）：成立，主要在 int4。**
   - **局部範圍內的比例**（|實際 − 局部預測| ≤ 25%）：全部 56%；int4 只有 14%（實際 ÷ 局部的中位數 1.52）；非 int4 76%（中位數 0.97）。
   - **偏離兩個方向都有**：L2 int4 是暴增（Up int4 實際 3795、局部 960；Gate + Up int4 實際 15166、局部 988），L27 int4 是飽和（實際約為局部的 0.6）。
   - **對排序的影響**：精確局部模型在局部範圍內的配對全部排對（610/610），整體仍錯 84 對；BC 錯誤中有 70 對屬於這一類，其中 39 對在 int4 配對。
   - **L0 的 int4 Gate／Up 判斷**連精確局部模型都錯，是唯一由非局部性決定的判斷。
3. **前面「L2、L27 是局部失效」的推論要修正。** 精確局部二階項 a2 在 L2、L27 的 int4 Gate／Up 判斷都對，BC 卻錯，所以這兩個是二階近似誤差，不是超出局部範圍。L2 雖然有暴增，局部曲率的順序仍然正確。
   - 二階近似誤差集中在 int4 配對：兩邊都含 int4 的 107 個錯誤中有 66 個。相同 M、B 的配對，BC 對 85 對，精確 a2 對 103 對（共 127 對）。
4. **建議**
   - **方向：不要加帶號項**，因為它不會從 calibration 轉移到新資料。應改善評估方式：非 int4 候選之間的 S 差異有很大比例是窗口雜訊，比較 criterion 時需要更多窗口，或改以期望損傷為目標。
   - **非局部：局部準則救不了**，應限制在 sink 層使用 int4 激活，或加入有限大小的檢查。
   - **二階近似：最可行的改善方向。** 用更接近真實曲率的估計（例如 FP32 點上的 Hessian-vector product，仍以 backward 為基礎）取代 empirical Fisher，至少在 int4 候選上。依本實驗，可以修正 L2、L27 的 int4 判斷與相同資源的配對；但成本是每個候選多一次 HVP 或 ±h 的前向。

## 1. 方法

**實驗 1**（全部 332 個候選；w、a、wa 三種模式；30 個窗口）
- 先在 tuning 窗口補做 backward 取得 gY：L0、L2、L14、L27 的 MLP 輸出梯度；window 0 與 cache 完全一致（差 0）。
- 對每個候選與窗口計算：
  - 精確一階項 F_s = Σ_{t≤126, j} gY·e，其中 e = Y_hat − Y_fp32；
  - Σ|gY·e| 與 Σ(gY·e)²。
- calibration 預測量（固定在 `plan.json`，沒有擬合係數）：

  | 名稱 | 定義 | 性質 |
  |---|---|---|
  | BC_total | native W + A | 平方 |
  | Fsq | Σ_cal F_s² | 平方 |
  | F_cal | Σ_cal F_s | 帶號 |
  | T_Y | F_cal + ½Fsq | Taylor 組合 |
  | T_BC | F_cal + ½BC_total | Taylor 組合 |

- 目標：tuning 上的 S = Σ_s ΔL_s（帶號）與 A = Σ_s |ΔL_s|（大小）。

**實驗 2**（activation-only 140 個候選；tuning 20 個窗口）
- 把 block 輸出誤差 e 乘上 ±h（h = 1/8）後重播下游，得到每窗口的精確局部係數：
  - 一階 a1 = (ΔL(h) − ΔL(−h)) / 2h；
  - 二階 a2 = (ΔL(h) + ΔL(−h)) / 2h²。
- 檢查：
  - a1 與梯度 F 的相對差中位數 0.005，相關 0.997；
  - 下游 base 與 block 研究完全一致（差 0）。
- oracle 預測量用 tuning 窗口自己的係數算，只用來解釋，不能部署：O1 = Σ(a1 + a2)、O2 = Σa2、O3 = Σa1。
- 「在局部範圍內」定義為 |S − O1| ≤ 0.25 × max(|S|, |O1|, 1)。

**配對與符號**
- 配對都在同一組（層 × 模式）內，|Δ目標| > 1（TAU），所有預測量使用同一組配對。
- S 是 summed CE；每 token 的平均 NLL 變化 = S ÷（20 × 127）。

## 4. 對兩個方向的意義

- **方向與抵消（假說 1）**
  - 現象是真的：平方 proxy 對應的是損傷大小；非 int4 候選的帶號 loss 有大量跨窗口抵消。
  - 但這部分無法從 calibration 預測，不應加帶號項。在目前 10 + 20 個窗口下，非 int4 候選之間的 S 排序有相當一部分是雜訊；BC 的 137 個「方向」錯誤大多屬於這類。
  - 改善應該放在評估端：更多窗口，或以期望損傷為準。
- **局部範圍（假說 2）**
  - 現象也是真的，集中在 int4：L2 暴增、L27 飽和、L0 的判斷由非局部性決定。
  - 任何局部（梯度二階）準則都救不了，需要限制格式（sink 層不用 int4 激活），或加入有限大小的檢查。
- **意外的第三個發現：二階近似**
  - 現行 Fisher／分解形式與真實局部曲率的差，造成 97 個錯誤，大多在 int4 與相同資源的判斷。
  - 這是三者中最可行的改善方向，但成本高：每個候選需要 HVP 或 ±h 的前向。

## 5. 耗時與限制

**耗時**

| 階段 | 時間 |
|---|---:|
| tuning backward | 36 秒 |
| 實驗 1 的區塊重播 | 49 秒 |
| 實驗 2 的 ±h 重播 | 1732 秒（L0 625、L2 586、L14 374、L27 142） |
| 分析 | 約 1 秒 |

**限制**
- 全部是事後分析，資料已被前面的研究分析過。
- oracle 預測量使用 tuning 窗口自己的係數，只用來拆解錯誤來源，不是可部署的 criterion。
- 實驗 2 只做 activation-only，沒有做 weight-only 與 weight+activation。
- 局部係數來自 h = 1/8 的對稱差分：截斷誤差為 O(h²)，a1 與梯度的一致性（相對差中位數 0.005）支持其準確度。
- 只有 4 層、5 種 activation 格式、Down 固定 FP32。
- 配對之間高度相關，配對數不能當成獨立樣本。
