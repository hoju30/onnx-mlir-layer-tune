## 性質與範圍

**做了什麼**
- 只在原 10 個 × 128-token calibration 窗口上做機制診斷，不是泛化檢定，沒有新文章，也沒有 bootstrap。
- 對象：L27 Down input 為主，L2 Down input 為預先指定的對照。兩層都報 int4／p4e1、int6／p6e1、int8／p8e1。
- 每次只改一層的 Down input；所有權重與其他 activation 都是 FP32，Down output 不量化。

**分解方式（固定）**
- e = Q(x) − x。
- μ_c = Σ e / 1280，以 float64 計算一次後固定。
- b = μ，施加在每個位置；r = e − b。
- 位置方向：r、M_P0·r、M_Rest·r，不重估 μ，也不重新中心化。

**loss closure**
- L27：Down → residual → final RMSNorm → LM head → CE。
- L2：Down → residual → 真實的 L3–L27（attention 與 FFN）→ norm → head → CE。

**沒有做什麼**：沒有改 U、V、量化器、range、搜尋、knee 或 pipeline；沒有 fine-tune、native，也沒有 float64 參考。

**單位**
- 內部用 summed CE 計算，表格最後除以 1270 targets（nat/token）。
- V 類 proxy 一律報 V/2，以便與 K_r = ½ dᵀHd 對照。
- 重點是排序，不是數值是否接近。

## 四個誤排逐一判讀

### 1. L27 int4–p4e1：原因 1、3、4 混合；純曲率 proxy 無解

**曲率**
- V_old/2 與 K_r 同號（都認為 Posit 的 r 較傷），所以旗標 A 為「否」。
- 但 V_old 的差距 −0.405 是 K 差距 −0.030 的 13.5 倍。

**位置配對（原因 1）**
- V_old → V_elem 讓差距從 −0.405 變成 +0.004，幾乎消除 proxy 的放大。
- 機制可用協方差恆等式 V_elem − V_old = Σ_c Σ_(s,p)(g² − mean g²)r² 說明，這一項 INT 為 +0.182、Posit 為 −0.227：
  - INT：殘差落在 g² 大的 Rest 位置，V_old_Rest/K_Rest = 0.52，被低估。
  - Posit：大殘差在 g² 小的 position 0，V_old_P0/K_P0 = 2.39，被高估。
- V_elem/2 對 K 的比值：int4 1.19、p4e1 1.06。

**跨 channel（原因 2）**：V_token 差距 −0.179，比 V_elem 更偏離 K，不支持。

**一階（原因 3）**
- F_r 差 +0.080，使局部模型 F + K 翻成 Posit 較好（+0.051），旗標 B 成立。
- O(α)/α 在 α ≤ 1/8 收斂到 F（小 α 支持）。

**高階（原因 4）**
- 實測 ΔL_r(1) 差 +0.172 中，局部 F + K 只解釋 +0.051（29%），其餘 +0.121 是有限幅度殘差 R(1)。
- Posit 在 α = 1 的偶次反應只有其 K 的 0.41 倍（INT 為 1.01 倍）；E(α) 的排序在 α 介於 1/8 與 1/4 之間翻轉。
- 這是有限擾動高階效應，不能稱為純一階或純二階。

**結論**：exact K_r（以及前輪 K_b）都偏向 INT，所以任何只估曲率的 proxy 都不會把這對排對。正確排序需要 signed 一階與有限幅度項；位置配對只能消除 proxy 的放大。r-only 排序與完整 ΔL_e 同號。

### 2. L27 int6–p6e1：原因 1 為主（A 支持）

- **曲率反號**：V_old/2 差 −0.209，K_r 差 +0.037。K 經 FD 與小 α 雙重支持，所以「局部方向曲率 proxy 失配」成立。
- **位置配對**
  - 低估：V_old_Rest/K_Rest，int6 為 0.43。
  - 高估：V_old_P0/K_P0，p6e1 為 2.83。
  - V_elem 讓差距縮到 −0.018，消除 91% 的錯誤，但仍差一點沒翻號。
- **其他 proxy**：V_token −0.073，不支持跨 channel；V_window +0.069 符號正確，但它是跨位置的經驗聚合，只算線索。
- **一階與高階**：F 與 K 同向（+0.069），F + K 與各 α 的實測排序全部一致，沒有高階翻序。Posit 的 E(1)/K = 0.51，有軟化但不改變排序。

### 3. L2 int6–p6e1：r 方向排序正確，誤排來自 P0 配對與全域 μ 抵消

**r 方向本身排對了**：V_old/2 差 −458，實測 ΔL_r(1) 差 −3.64；Posit 的 r 在所有 α 都比 INT 傷，V_old 對 r-only 排序正確。

**完整誤差卻是 Posit 較好**（ΔL_e 差 +0.275）

| 項目 | Posit p6e1 | INT int6 |
|---|---|---|
| ΔL_b（mean-only） | 2.647 | 0.101 |
| ΔL_r（r-only） | 3.859 | 0.215 |
| ΔL_e（完整） | 0.052 | 0.327 |
| I_br | **−6.454** | +0.012 |

**來源**
- L2 每個窗口的 position 0 都有約 3000–3800 的 Down-input spike。
- p6e1（maxpos 256）把它截斷，產生最多約 3500 的誤差。
- 這個誤差被平均進全域 μ（最大 25），於是 b 在所有 Rest 位置加入一個假的同向平移，r_Rest 帶著對應的 −μ。兩者在真實模型中互相抵消。
- BC 把 U(b) 與 V(r) 當成獨立項相加：Posit 的 U/2 2.66 加 V_old_Rest/2 3.58，都是這個分解產生的假象。

**P0 位置配對（已證明，P0 方向經 FD 確認）**
- V_old_P0/2 為 455.3，K_P0 只有 0.0795，放大約 5700 倍；同位置配對的 V_elem_P0/2 為 0.195。
- 原因：spike channel 的全位置平均 g² 遠大於 position 0 本身的 g²。

**INT 真正的損傷**
- INT 的 range 被 spike 撐到 [−3012, +3787]，int6 步長約 108，一般 token 的輸入（|x| < 11）全被量化為 0。
- 所以 INT 的 e 在 Rest 約等於 −x，這是 0.33 nat/token 的真實損傷。

**局部曲率**：K_all 與 K_Rest 數值未定，不能判斷局部 r 曲率的排序，也不能分出一階／高階。

**結論**
- 這對不屬於規格所列的四類 r 方向原因之一（r-only 的排序本來就對）。
- 誤排是 ① P0 位置配對的巨大放大，加上 ② 全域 μ 分解造成的 b／r 假抵消（BC 加總時沒有交互項）。
- 前輪的 spike 分組（全域 μ、不重新中心化）與同位置配對（仍加全域 U）各只處理其中一半，所以都沒翻過來。這是事後解釋，不是已驗證的修正。

### 4. L2 int8–p8e1：與 3 同一機制

- **r-only 本身**：ΔL_r(1) 差 −0.015，幾乎打平；E(α) 的排序在 α = 1/2 與 1/4 之間翻轉。
- **proxy 放大**：V_old/2 差 −80.5 被放大；V_elem 差 −0.004，約等於 0。
- **P0 配對**：V_old_P0/2 80.34 對 K_P0 0.0026，約 3 萬倍；V_elem_P0/2 為 0.038。
- **全域 μ 抵消**：ΔL_e 差 +0.317，Posit 的 I_br = −0.776（mean-only 0.551、r-only 0.222、完整 −0.004）。
- **INT 側**：int8 步長約 27，一般 token 同樣大多被量化為 0（ΔL_e 0.313）。

## 兩個同位元對照

- **L2 int4–p4e1**（BC 選對 INT，新文章 −3.59）
  - V_old 的放大與全域 μ 抵消同樣存在（Posit 的 I_br −7.39）。
  - 但 p4e1 在 Rest 的粗量化損傷本來就大（ΔL_e 3.94 對 0.32），所以排序沒有被翻轉。
  - 「BC 排對」不代表各項都估準。
- **L27 int8–p8e1**（新文章 +0.0023，未定；本批 calibration ΔL_e +0.007）
  - A 支持：V_old 認為 INT 的 r 較好，K_r 則認為 Posit 較好。
  - V_elem、V_token、V_window 都與 K 同號，F 幾乎為 0。
  - 這是 L27 另一個位置配對失配，只是損傷差很小。

**控制結果**
- 兩層的 F、V_old 拆分都可加（相對誤差 ≤ 3.5e-16）。

**L2 的位置交互**（attention 之後，保留正負號，不當控制失敗）

## 已證明／僅線索／未定

**已證明**（限這 10 個反覆使用的 calibration 窗口，數值經 FD 與小 α 驗證）
- L27 六格式的 K_r、F_r 數值與排序。
- L27 6-bit、8-bit 的 V_old 與 K_r 反號。
- L27 4-bit 的 K_r 偏 INT 而 r-only 偏 Posit，且局部 F + K 只解釋 29% 的差距。
- L2 的 K_P0 與 V_old_P0 的數千到數萬倍放大。
- L2 的 b／r 實測抵消（I_br）。

**僅線索**
- V_elem 在 L27 三對中最接近 K，而且最接近的是數值大小，排序並沒有全部修正。
- V_window 在 L27 6-bit 排對。
- V_token 不支持跨 channel 解釋。
- L2 的窄尺度非線性來源未查（例如是否與 attention 中某些極小的 q／k norm 有關，沒有測）。
- 「位置配對 + 分組平均」能否修正誤排：本輪沒有計算任何新分數。

**未定**
- L2 涉及 Rest 的局部曲率 K 與一階／高階分解。
- 任何結論能否轉移到新文本或其他層：沒有新文章，也沒有跨層掃描。

## 下一個具體低成本修正假說（只提出，未測試）

**假說：對 spike 行分組重新求平均並同位置配對（BC Eq.5 的分組版）**

**定義**
- 沿用 down spike diag 已凍結的 spike 行規則（a_st = max_c |h_stc| ≥ 6 × median；本批 L2、L27 恰為 10 個 position-0 行），不新增或調整門檻。
- 一般行 N：只用 N 行估 μ_N，照原 BC 計算 V_N 與 U_N。
- spike 行 S：不參與 μ，改用同位置梯度配對的未中心化能量 T_S = Σ_(S,c) g² e²。
- 總分 T = V_N + U_N + T_S。
- 沒有 spike 行的層，T 與原 BC 逐位元相同。

**與先前做法的差別**
- 前輪 spike 分組：μ 仍是全域、組內不重新中心化，所以假的 U 與 Rest 殘差還在。
- 前輪同位置配對：仍加全域 U。
- 本輪的資料顯示，L2 需要兩件事同時處理：spike 行不能汙染 μ，spike 行的誤差要配上自己的梯度。

**依本輪數字的預期（不是結果）**
- L2 6／8-bit：Posit 的分數會從數百 nat 量級降到約 V_elem_P0 加上小 Rest 項（p6e1 約 0.2 加少量），可能低於 INT（約 0.6–0.7），因而翻成 Posit。
- L2 4-bit：應維持 INT。
- L27 4-bit：**不會修好**（K_r 與 K_b 都偏 INT）。
- L27 6-bit：不確定，Rest 內的配對同樣重要。

**成本**
- N 行統計就是現有累加器加上一個行遮罩。
- S 行需要同時取得 g 與 e，但每窗口只有約 1 行（每層 10 × 3072 個數值）。
- spike 遮罩可在梯度 pass 自身的前向計算，不需要額外 pass。

**檢驗方式（另立計畫）**
- 預先登記；新文章；全部 28 層的 84 個同位元對，對照原 A；報修正數與新增誤排數。
- 不掃門檻；沒有 spike 行的層須逐位元相同。
- 即使通過，也還需要完整配置與 native 驗證。

## 揭露

**冒煙測試**（計畫前，scratchpad，同一批 10 個 calibration 窗口；細節記於 plan.json）

- **第一次（04:55–04:59）**：用最初的容差，三項控制失敗。
  - L2 batch 的 g 差 1.05e-4，超過 1e-4。
  - L27 F_b 與 U 的同後端重現差到 2.6e-3／2.5e-4，超過 1e-4；兩者都是正負相消的和。
  - L2 合成方向的 FD 不收斂。
  - 同時看到的結果：L27 全部確認；L2 Rest 方向不收斂；窗口 0 的窄尺度非線性。
  - 另以 scratchpad 探針 `probe_l2.py` 確認：position-0 spike 約 3000–3800、L2 INT range 為 [−3012, 3787]。
- **計畫前的修改**
  - FD 改為也逐窗口判定，並新增 HVP 機制控制。
  - L2 合成方向改為只報告。
  - batch 的 g 容差改為 1e-3。

  - V_pair 改以 T_pair − U 比對。
  - 新增各 α 的排序報告。
- **第二次（05:05–05:09）**：全部控制通過，並已看過全部結果、旗標與圖。
- **正式執行**：與第二次冒煙逐位元相同（losses、raw 完全一致）。它是同一批資料上的確定性重跑，不是獨立驗證。
