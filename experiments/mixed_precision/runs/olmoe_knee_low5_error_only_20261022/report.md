# OLMoE 正常 knee：≤5-bit activation error-only refresh（E5）

日期：2026-10-22
腳本：`run_olmoe_knee_low5_error_only.py`（plan → controls → refresh ×9 → 端到端 E5 → check → freeze → data → eval → analyze）
輸出：本目錄

**背景**
- 全節點 error-only E 沒有確認改善 static BC，但它的更新只要約 25 秒。
- 本輪依你的要求，檢驗把更新範圍縮小到 q0 中 ≤5-bit 的投影（E5），能否改善品質並再降低成本。
- 這是看過 E 結果後才提出的新假說，plan 中已記錄這個背景；本輪在新文章上檢驗一次。

**本輪的範圍**
- A、B、E、D5 沿用凍結的配置；C、D4 只用於交叉評分的診斷。
- 沒有重選 knee；沒有修改 BC；沒有訓練或更新參數；沒有第二次 refresh；沒有新的搜尋演算法；沒有修改正式 pipeline 預設。
- 不接著測 ≤6-bit，也不更換選點規則。
- 所有 stage 都用同一份腳本（sha `dddadd8c…`），沒有修訂（`amendments.json` 為空）。

## 回答六個問題

**1. E5 是否改善 static BC？**
- **沒有。** 點估計 +0.00003，幾乎為 0。
- 校正區間能排除的：大於 0.00075 nat/token 的改善，或大於 0.00079 的變差。
- 不能排除的：0.0007 以內的小改善或小變差。

**2. E5 是否優於全節點 E？**
- **沒有確認。** −0.00037，校正 CI [−0.00101, +0.00027]。
- 點估計上，E5 比 E 好一點。本批的 E − A 是 +0.00039，所以這比較像是 E5 少了 E 的那部分不利改動，而不是 E5 本身帶來收益；但兩者都沒有確認。
- 依指示：即使 E5 優於 E，也不等於優於 A。

**3. E5 是否保留 B 的品質？**
- **證據不足。** E5 − B = +0.00060，校正上界 +0.00137 > +0.0005。
- 本批的 B − A 本身也沒有確認（−0.00057），所以 E5 要保留的收益本身就不確定。

**4. 在相同的目標集合下，E5 和 D5 哪個更有證據支持？**
- **兩者都沒有。**
  - E5 − D5 = +0.00032，95% CI [−0.00039, +0.00102]，未確認。
  - D5 − A（−0.00029）和 E5 − A（+0.00003）也都沒有確認。
- **配置面（描述性）**：同樣只針對這 1512 個投影更新，兩者改動的規模差很多。
  - D5 對 A 改了 134 個投影（目標集合內 126、外 8）。
  - E5 只改了 32 個（集合內 31、外 1）。
  - 也就是說，只刷新 error 幾乎不改變配置；更新 sensitivity 才會帶來大量的重新分配。
  - 這些改動對 loss 的影響，本批資料解析不出來。

**5. 省下多少時間？**
- **額外時間**（3 次中位數）：

  | 條件 | 秒 | E5 少多少 |
  |---|---:|---|
  | E5 | 22.4 | — |
  | E | 27.5 | 5.1 秒（−19%） |
  | B | 83.2 | 60.8 秒（−73%） |

- 省下的幾乎全是候選 activation 誤差：E5 只算目標投影需要的 2,538 個 slot 欄位，E 算全部 5,085 個，耗時 3.6 秒對 8.0 秒。
- 載入與量化（約 11 秒）、forward、剪枝與搜尋（約 5 秒）兩者都要付。所以更新的投影減半，總時間只少 19%。
- **從零到最終配置**：
  - E5 單次實測 192.8 秒；
  - 上一輪 E 的單次實測 192.1 秒（歷史值）、A 170.5 秒（歷史值）。
  - 換言之，E5 比 A 多約 22 秒（+13%）；比 E 的差異在不同輪次與負載之間幾乎看不出來（輪內的額外時間差是 5 秒，約為總流程的 3%）。
- **計時注意**：本輪計時期間，機器上有其他程式（瀏覽器的 renderer 程序）佔用 CPU，load average 約 2；B 第 1 次因此慢到 96.2 秒。三種方法交錯執行，所以輪內比較仍然公平；但本輪的絕對秒數比前幾輪高約 3–10%，跨輪比較只能當作參考。

**6. 是否值得保留為可選步驟？**
- **不值得。** E5 沒有改善 A，也沒有確認優於 E 或保留 B 的品質。它只比 E 省約 5 秒。
- **[推論] 五批 knee 資料的整體圖像**（各批單獨配對，不合併、不跨批相減；見後文表格）：
  - 完整 refresh B 相對 A，五批的點估計都是負的（−0.0005 到 −0.0012），其中兩批在 95% 水準確認；
  - 所有只更新一部分的變體（C、D4、D5、E、E5），相對 A 都沒有確認過；
  - 全節點 error-only E 兩批的點估計都是正的（變差的方向）。
- 結論只適用於本模型、本 calibration、本 knee 和 GPU QDQ。依指示，不接著測 ≤6-bit 或其他規則。

## E5 的定義與實作（`plan.json`、`low5_nodes.json`）

**目標集合**：從 A（= q0_knee）重算並凍結，FORMAT_BITS[w] ≤ 5 或 FORMAT_BITS[a] ≤ 5，以投影為單位。
- 共 1512 個（169 個 int4 加 1343 個 int5 weight），和 D5 的目標集合完全相同；其外 1539 個。
- 分布在 595 個 expert；這些 expert 拿到 FP32 calibration 73,322 個 rows（44.8%）。
- 需要計算誤差的 slot 欄位共 2,538 個，全部是 5,085 個：x_in 588、gate_y 582、up_y 492、down_x 438、down_y 438。

**成本**
- **weight**：每一列都逐位元等於 A。
- **sensitivity**：全部使用上一輪已驗證的 static G2／GS 快取（`runs/olmoe_knee_error_only_20261022/work/runs/static_gc/`，hash 核對）；沒有計算任何新的 sensitivity。
- **目標投影的 activation**：所有候選格式，A_E5(f) = Σ_slots,c [G2_static·var_new(f) + GS_static·μ_new(f)²]。
  - 新誤差在和 E 相同的位置計算，以 q0 的 routed rows 正規化；G2／GS 維持 static 尺度；ranges、scale、量化器都固定。
- **非目標投影的 activation**：逐位元等於 A。即使為了 gate 或 up 目標計算了共用的 x_in，也不會改寫另一個非目標投影的成本列。

**選擇性 forward-only 實作**
- 延用 E 已驗證的觀測路徑：`inference_mode`、不呼叫 `retain_grad`、`AutogradGuard` 計數 autograd 呼叫。
- 完整的 q0 模型照常跑 forward，路由與 hidden state 不變。
- 只對目標投影需要的 slot 計算候選誤差：gate 需要 x_in、gate_y；up 需要 x_in、up_y；down 需要 down_x、down_y。
- 不是先算完 E 再遮罩：3 次執行都只算了 2,538 個欄位。
