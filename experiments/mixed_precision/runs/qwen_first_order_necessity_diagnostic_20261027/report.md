# 一階方向資訊必要性診斷（事後探索）

日期：2026-10-27。腳本：`run_qwen_first_order_necessity_diagnostic.py`。
計畫：`analysis_plan.md`／`analysis_plan.json`，04:09:58 寫入，容差與分類規則都在任何配對比較前固定。
來源：`source_manifest.json`。

**性質**
- 只重新聚合三個既有 GPU run 已保存的 C／N 陣列。沒有任何模型推論、梯度、proxy 重算或 GPU。
- 所有 C 與 N 先前都已看過，所以本輪**全部新比較都是事後探索**，不是確認性實驗。

**評分器**（每 token，相對同背景的 activation f16）

| 名稱 | 定義 |
|---|---|
| S | g_u·Δu |
| K_full | 輸出端 K2_actual = ½Var_p0(實際 logit 差)；不是全模型 Hessian |
| K256 | Khat256 |
| S+K_full | S 加 K_full |
| S+K256 | S 加 K256 |

**核心比較**
- K_full → S+K_full：一階的額外價值。
- K256 → S+K256：低成本版是否有同樣現象。
- K_full 對 K256：二階壓縮的影響。

「S+K 比 S 好」只代表補二階有幫助，不拿來證明一階必要。

## 首頁：六個問題

先說一個結構性事實：K ≥ 0，且 f16 的 K = 0。所以**單用 K 永遠不會把任何格式排在 f16 前面**，argmin 必然選 f16。凡是「量化格式真的比 f16 好」的配對，K 必錯，只有帶正負號的項才可能修正。因此真正要檢驗的是：**S 的正負號在新文章上對不對**。

### 1. 完整二階補一階，是否真的修正了排序？修正幾對、破壞幾對？

K_full → S+K_full，選擇集 28 對：

| 情境 | C 修正／破壞 | N 修正／破壞／都錯 | N 未定 | 同 bit 三對（N） |
|---|---|---|---|---|
| L27 U | 3／0 | 0／0／0 | 3 | 都對 |
| L27 F | 2／0 | **2／0**／0 | 1 | 都對 |
| L27 W | 2／0 | **2／0**／0 | 1 | 都對 |
| L26 U | 3／0 | **2／0**／0 | 3 | 都對 |
| L26 F | 3／0 | 0／**3**／1 | 2 | int8–p8e1：C 修正、N 破壞 |
| 小計（5 個情境 × 28） | **13／0** | **6／3**／1 | 10 | |
| L26 coverage 120 組（每組 28 對，共 3360） | **383／34** | **106／137** | 360 | int8–p8e1：29 組 C 修正、N 破壞；其他兩對全都對 |

- 在 C 上，補一階幾乎只有修正。
- 在既有 N 上，結果兩極：
  - L27 F／W、L26 U 有修正，且這幾個情境沒有破壞。
  - L26 F 與 L26 coverage（也是 F 背景）的破壞多於修正。coverage 的 12 個 pool 中，11 個淨值 ≤ 0。

### 2. 改善只在 C，還是既有 N 也成立？

只部分成立。

- **在 N 也成立的修正**，全部是 **p8e1 對 f16／bf16** 這兩對：p8e1 在 N 上確實比 f16 好的情境（L27 F/W、L26 U），一階把它排對了。另外 K256 版還多一個 int8–int4（見第 4 題）。
- **只在 C 成立的修正**，主要是含 **int8** 的配對：
  - L26 F：f16–int8、p8e1–int8、int8–bf16。
  - coverage：f16–p6e1、p6e1–bf16、p8e1–int8。
  - 這些配對在 C 上一階排對，在 N 上則被證明是錯的。
- 在 L26，S+K_full 與 C 實測幾乎完全吻合：D_C − (S+K_full) ≤ 7e-4，int8 只差 1e-4。所以這些破壞**不是近似誤差**，是 **C 到 N 的轉移失敗**。例如 L26 F 的 int8：C −0.0009，N +0.0096。

### 3. 其他投影已量化時，一階的額外價值是否更明顯？

**沒有一致的方向，兩層相反**。

- **L27**：價值出現在量化背景。
  - F、W 的修正在 N 上成立；U 的同一批修正在 N 上未定（U 的 p8e1 在 N 上與 f16 無法區分）。
  - 配對文章分析：f16–p8e1 的 N 差，從 U 到 F 增加 +0.0092 [+0.0074, +0.0109]。
  - 同一對在 C 上幾乎沒變（+0.0042 → +0.0045），S 只增加 +0.0028。也就是說，背景依賴主要出現在 N，C 並沒有反映出來。
- **L26**：方向相反。
  - U 有 N 成立的修正（p8e1 比 f16 好 −0.0017）。
  - F 則有 3 個破壞，都含 int8。
  - 從 U 到 F，S 對 f16–int8、p8e1–int8 的差各增加 +0.0064／+0.0132，跟著 C 翻了號；但 N 上 int8 仍然較差（N 差的變化 +0.0005 [−0.0015, +0.0027]、+0.0070 [+0.0046, +0.0095]，都沒有翻號）。
- 判讀：
  - 只能說 L27 的結果**支持背景相關的一階價值**（只在 F/W 成立）。
  - L26 不支持「其他投影量化時一階價值較大」。
  - 本輪不能寫成已證明誤差抵銷機制，也不能說前層量化都需要一階。

### 4. 完整二階與 top-256 的結論是否一致？

- **L27／L26 的 10 個情境**：方向一致。
  - 30 個翻轉中，K256 獨有的只有兩種配對（共 4 列）：
    - L27 U／F／W 的 int8–int4：K256 把 int8 排在 int4 後面（完整 K 是對的），S 把它修回，N 成立。這是**壓縮造成的錯被一階剛好補回**，不是一階本身的價值。
    - L26 U 的 p6e1–int8：C 修正，N 未定。
  - 選到的格式在 K_full 與 K256 下都相同。
- **coverage**：同方向，但 K256 明顯更差。
  - N 修正／破壞：K_full 為 106／137，K256 為 81／201。
  - 選擇後果：S+K_full 比 S+K256 好 0.0005–0.0013（各格平均）。
  - 原因：K256 漏掉 tail 方差而低估 K（K_full − K256：p6e1 +0.003、int8 +0.001），讓 S 的影響更大，更常選到 p6e1。

### 5. 效果是否只限 L27、某個 bit 或某個候選？

N 成立的一階價值**只集中在 8-bit Posit 對 f16／bf16**。

| 範圍 | 情況 |
|---|---|
| p8e1 對 f16／bf16 | 一階價值唯一在 N 成立之處：L27 F/W、L26 U |
| 4-bit、6-bit 同 bit 對 | 所有情境 K 單獨就已全對，一階既沒修正也沒破壞 |
| 8-bit 同 bit 對 int8–p8e1 | 只在 L26 F 與 coverage（29/120 組）被一階翻到 int8 一邊，N 全是破壞 |
| 層別 | L27 與 L26 都有 N 成立的修正，所以不只限 L27；但在哪個背景出現，兩層相反 |

### 6. 哪些結果值得用新文章與其他預先指定層做下一輪確認？

- 值得確認的只有一個窄假設：「**p8e1 對 f16／bf16 這類 8-bit Posit 配對，S 的正負號能預測新文章上的方向**」。下一輪可以預先指定其他層、U/F 兩背景、全新文章。
- 不建議進一步確認的：
  - **含 int8 的配對**：L26 的 N 已經呈現破壞。
  - **把 S 加進選擇器**：coverage 中 S+K 選出的格式在新文章上**沒有任何一組比 K 所選的 f16 好**（120 組中 0 組）。變差的組數：S+K_full 74 組，S+K256 93 組。
- 本輪結論：**目前沒有證據支持把一階一般性地加入 criterion**。它在特定格式和背景下有價值，但同一機制在其他情境會依校準資料錯誤地偏向 int8／p6e1。

**背景定義**（`run_qwen3_conditional_signed_score.background`、`run_qwen3_l26_suffix_bridge.background`）
- U：其他投影全部 FP32。
- F：其他 195 個投影依 A（`qwen3_spike_endpoint_pipeline_20261026/configs/A_auto.json`）。
- W（只有 L27）：第 0–26 層的 Down 用 A 的權重格式、activation FP32，其他全部 FP32。

**其他定義與規則**
- activation 的 input／output 一起換格式。
- L26 的 Δu 經過真實 block27 重播，不是免後綴重播的局部 criterion。
- N 只用各 run 自己的文章。同一 run 內 U/F/W 使用同一批文章，背景比較用配對文章。跨 run 不配對，也不合併。
- **原 BC**：無法比較。native `table.json` 的 act cost 是在 FP32 背景、FP32 目標權重下，以 native 誤差統計和不同單位、逐節點相加的形式計算的，與 F/W 以及 U 的 INT8／INT6 目標權重都不匹配。各 run 只寫死「BC = f16」（A 的選擇）。
- **缺失資料**：L26 的 W 背景、coverage 的 U／W 背景從未量測，沒有重算。

**預先固定的規則**（`analysis_plan.json`）
- 平手容差 τ = 4e-7 nat/token，依據是 L27 已知 K2_actual 與 K2_affine 的數值差。它同時用於分數差與 dD_C。
- 比值 |dS|/(|dK|+4e-7)：|dK| ≤ τ 記為「K 近零」，不算比值，只作描述。
- N 方向沿用各 run 的 CI 規則：20000 次文章 bootstrap，CI 跨 0 為未定。

## 7. 限制

- 全部是事後探索：所有 N 先前都看過，大量配對 CI 只是描述，沒有多重比較校正。
- 情境數很少：只有 L27、L26 兩層，各 1–3 個背景，同 bit 對也只有 3 對。
- 層間差異不能解讀成純層位置效應：兩層的目標權重格式（int8／int6）和 N 文章都不同。
- 「K 單獨永遠選 f16」是結構性的，所以選擇結果不能單獨證明或否定一階的必要性；同 bit 排序已一併列出。
- 原 BC 無匹配資料，未比較。
- P0／Rest 只是最終 CE 位置的分解，不是 spike 或源頭位置的因果效應。

## 8. 結論

- 在 C 上，補一階幾乎只修正、不破壞。
- 在既有 N 上，它只在「p8e1 確實比 f16 好」的情境（L27 F/W、L26 U）修正了 p8e1 對 f16／bf16 的排序。
- 在 L26 F（含 120 個 coverage 組）中，它依校準資料把 int8／p6e1 排到 f16 前面，在 N 上的破壞多於修正。所選格式也從未比 f16 好。
- 一階價值的背景依賴在兩層方向相反，與 top-256 壓縮的交互作用只會放大這些錯誤。
- 結論：**目前沒有證據支持把一階一般性地加入 criterion**。唯一值得另外預先登記確認的，是 8-bit Posit 對 f16／bf16 的方向預測。

本輪到此為止：沒有修改正式 criterion、BC、配置、量化器、ranges 或 MILP／knee，也沒有擴大實驗或產生啟用規則。
