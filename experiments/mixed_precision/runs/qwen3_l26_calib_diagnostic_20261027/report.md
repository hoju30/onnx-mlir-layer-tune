# L26 校準選擇反轉：既有資料的事後診斷

日期：2026-10-27。

本輪只對 `qwen3_l26_suffix_bridge_20261027` 已保存的 C／N 陣列作 CPU 分析，另重新 tokenize 原始校準文字核對來源。沒有新模型推論、文章、梯度、range、配置或 selector；全部新增分析均為事後探索，不能稱為新資料確認。

結論：原 C 的 10 個窗口全來自同一篇文章；INT8 的平均收益由正負效果抵銷，刪一窗口後可能反轉。top-256 在完整 C 的排名雖與真值相同，卻有足以放大微小收益的樂觀偏差。這些是繼續測文章覆蓋與選擇穩定性的具體動機，還沒有證明換 calibration 就能修好。

## 1. 來源核對：10 個窗口，實際只有一篇文章

重新讀原 parquet、用原 tokenizer tokenize，逐 token 驗證：

```
native_eps_fix_20261014/qwen3/calib_inputs.npy
== qwen3_prepare_20261011/validation_tokens.npy
== tokenize(join(WikiText-2 validation text rows))[:1280].reshape(10,128)
```

三者完全相同。C 是 WikiText-2 validation 開頭文章 **Homarus gammarus（歐洲龍蝦）**的前 1280 tokens，含開頭空白；覆蓋原串接文字 `[0,5339)` 字元，raw rows 0–28。第二篇 Frank Headlam 在 row47、char8764 才開始；第一篇加前導空白總共2156 tokens。

N 則是 WikiText-103 train 的128篇隨機文章，每篇兩個128-token窗口。C／N同時有文章覆蓋、來源split、文章內起點與位置重設方式的差異，不能只歸因「10太少」。C十窗口也不能當作十個獨立文章來bootstrap或宣稱統計信心。

證據：`source_audit.json`，含token等值、文字範圍及parquet／tokenizer／npy hashes。

程式鏈：`qwen3_prepare.py:148–155`取validation開頭；`run_native_bc_pipeline.py:182–185`載入prepare validation、`:394–395`保存calibration，`:433–446`用同一批C建立ranges。L26沿用固定ranges，沒有在N重校準。這份來源事實不能單獨解釋先前在同一C內的BC／實測誤排。

## 2. 微小收益是抵銷，不是十窗口一致改善

條件固定：L26 Down、weight INT6、activation候選、F背景、相對f16。數值為nat/token。

| 窗口（從0編號） | INT8 的實測 D |
|---|---:|
| 0 | +0.03927614 |
| 1 | +0.01076991 |
| 2 | −0.01785874 |
| 3 | −0.01647709 |
| 4 | −0.00448586 |
| 5 | +0.00298265 |
| 6 | +0.00118514 |
| 7 | −0.00851288 |
| 8 | −0.01636747 |
| 9 | +0.00048967 |

5個有利、5個有害，平均 **−0.00089985**，窗口標準差 **0.01703579**。標準差僅描述窗口間變化，不將這些相鄰窗口視為獨立文章作推論。

對固定per-window結果，逐一刪一列後重新聚合及選擇：

| 選擇依據 | INT8次數 | f16次數 | 何時改成f16 |
|---|---:|---:|---|
| C實測D | 7 | 3 | 刪窗口2、3或8 |
| S_u＋完整K2 | 7 | 3 | 刪窗口2、3或8 |
| P256 | 10 | 0 | 沒有 |

只有S_u則10次都選activation INT6。這是固定分數的影響分析，沒有真的以9窗口重跑GEMM／校準／梯度。刪一窗口結果不是十次獨立實驗，也不是可直接部署的規則。

另列舉十窗口的1023個非空子集，結果見`all_fixed_score_subsets.csv`。例如252個五窗口子集，C實測選INT8 139次、f16 96次、p8e1 16次、bf16 1次；P256則選INT8 149次、f16 86次、p8e1 16次、bf16 1次。這些重疊子集不是獨立校準集，不能拿比例當新文本的成功機率，或依N表現選最有利的子集大小。

## 3. 完整C排名相同，仍有影響微小margin的近似偏差

F／INT8：

| 量 | nat/token |
|---|---:|
| C實測D | −0.00089985 |
| P256 | −0.00228313 |
| P256−D | **−0.00138328** |
| 遺漏tail方差 K2_affine−Khat256 | +0.00124399 |
| KL−K2_actual | +0.00013889 |

P256在10個窗口中全部比真值更負，每窗口偏差介於−0.00193008與−0.00074066。平均偏差大於原本的微小收益，因而讓P256看起來比實測更支持INT8，刪一窗口也不改選。

原先「完整10窗口的排序沒有被近似改變」仍成立；新增結論是「近似沒有因此對小margin完全無影響」。更穩定地選同一格式，也不等於跨文本更可靠。

## 4. INT8 的 C→N 反轉主要在末端 Rest

各位置貢獻都除以127，因此可加成總nat/token。

| 最終CE位置 | C | 已看過的N | N−C |
|---|---:|---:|---:|
| P0 | +0.00013174 | +0.00019273 | +0.00006099 |
| Rest（1–126） | **−0.00103159** | **+0.00940204** | **+0.01043363** |
| All | −0.00089985 | +0.00959477 | +0.01049463 |

N有101／127個末端CE位置的平均損傷為正；Rest按順序分四段，四段都為正。這裡的P0／Rest指最終loss位置，不能當成源token擾動的因果歸屬。

不同格式的轉移也不同：

- activation INT6：All位移+0.01561236，Rest位移+0.01536092。
- Posit8：All位移+0.00136746，幾乎全在P0（+0.00137458），Rest只變−0.00000712。

因此本輪觀察不支持把所有格式簡化為同一個整體loss平移；也不支持將INT8反轉只歸因P0。

## 5. 支持的下一個最小實驗

先保持F配置、INT6權重、原量化器與ranges不變，以相同1280個校準token，比較「同一篇的10個窗口」與「10篇各1窗口」的選擇穩定性。優先用校準實測D作對照，分清資料選擇問題，再討論近似；不應只靠P256的刪一窗口穩定就宣稱可靠。

為分開來源與文章覆蓋，後續設計宜把WT2 validation／WT103 train與單篇／多篇分開比較，抽樣規則與重複次數先登記；不得按本輪N結果挑來源、窗口或門檻。原ranges先固定，避免同時改變評分資料與量化器。若要重校準range，另作獨立因子。

凍結選擇規則後，再用全新文章確認。暫不修改正式BC、增加一個任意margin門檻、擴到L25或重跑完整pipeline。現在還不能宣稱單篇覆蓋就是唯一原因，或多篇校準必然改善。

## 重現與檔案

從`experiments/mixed_precision`執行，指定新的空輸出目錄：

```bash
PYTHONPATH=qwen35_assets/python_deps ../../venv/bin/python run_qwen3_l26_calib_diagnostic.py --out-dir runs/qwen3_l26_calib_diagnostic_replay
```

- `analysis_scope.json`：事後分析界線與來源hash。
- `source_audit.json`：實際token來源核對。
- `calibration_windows.csv`：逐窗口分數／實測／位置分項。
- `leave_one_window_out.csv`：固定結果刪一窗口選擇。
- `all_fixed_score_subsets.csv`：全部子集的固定分數重聚合。
- `summary.json`：F／U全部格式、位置與穩定性摘要。

未變更原實驗產物或正式pipeline。全部新增結果都屬既有資料的探索性診斷。
