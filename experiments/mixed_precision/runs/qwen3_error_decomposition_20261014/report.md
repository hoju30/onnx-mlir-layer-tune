# Qwen3-0.6B Gate／Up 誤差拆解：變異項、平均偏差項與各位置的貢獻

日期：2026-10-14　腳本：`experiments/mixed_precision/run_qwen_error_decomposition.py`　資料：`runs/qwen3_block_criterion_20261014` 的快取、候選與 loss（PyTorch 模擬；該研究已用 native 核對）

**這是事後診斷**：候選和 tuning 結果先前都已看過，所以以下相關係數只能用來解釋，不能當作已驗證的方法改善。

## 結論

1. **節點層級（BC 的激活項 A）：**
   - 主要是變異項，佔 86–100%。平均偏差項只在 int4（L27 34–38%、L2 10–14%）和 p6e1（L14 18%）比較明顯。
   - p6e1 的平均偏差項幾乎全集中在單一 channel（91–99%）。
   - position 0 不主導 A：L0、L2、L14 排除 position 0 後，A 仍是原來的 0.95–1.01 倍。只有 L27 的 position 0 佔 58–89%，原因是那裡的梯度大，誤差本身並不大。
2. **預測 loss（activation-only 與 weight+activation 共 8 組，組內 Spearman 對 tuning S）：**

   | 預測量 | 數值 |
   |---|---:|
   | 節點變異項 | 0.858 |
   | BC 的 A（變異 + 平均偏差） | 0.852 |
   | 節點平均偏差項單獨 | 0.768 |
   | 節點層級排除 position 0 | 0.843 |
   | block 輸出 Y 的 MSE（全部位置） | 0.785 |
   | Y 的 MSE（排除 position 0） | 0.887 |

   - 平均偏差項沒有提供額外的預測力。
   - 節點層級不需要、也不適合排除 position 0。
   - block 輸出 Y 被 position 0 的誤差能量主導，排除後明顯改善。
3. **介入實驗：position 0 的誤差不是無關，而是「量級和誤差能量不成比例」。**
   - **L0 int4**：position 0 只佔 Y 誤差能量約 1%，卻造成大部分 loss 增加。Gate int4 的 calibration 損傷有 80% 來自 position 0，tuning 是 63%。
   - **L2**：
     - Up int4 的 position 0 佔 78%（calibration）與 62%（tuning），position 0 和其他位置還有 +656 的放大交互作用。
     - 但 int8、p6e1、p8e1 的誤差能量幾乎全在 position 0（67–100%），對 loss 的影響卻約為 0 或為負。
   - **L27**：激活誤差在 position 0 佔 24–98% 的能量，對 loss 的影響卻約為 0 或為負；損傷幾乎全在 position ≥1。weight-only 時則相反，position 0 的單一預測主導，而且正負號不定，例如 Gate int4 −62、Gate p6e1 +71（tuning）。
   - 所以 position 0（attention sink）的敏感度強烈非線性：小誤差可能造成大損傷（L0），大誤差也可能沒影響（L2 的溫和格式、L27）。誤差能量（MSE）和逐元素一階梯度權重（gY²e²）都描述不了它。
4. **意義**：
   - 先前「排除 position 0 後排序變好」的原因，是 MSE 對 position 0 的權重錯了，不是 position 0 的誤差真的不重要。直接排除會丟掉 L0 int4 這類真實損傷。
   - 要處理 outlier，應把 position 0 當成一個需要單獨量測敏感度的位置，不能用同一套逐元素權重，也不能直接丟掉。

## 1. 方法

**節點 tap**：Gate／Up 的 x（該分支的 X 複本）與 y（zg／zu），沿用 per-consumer QDQ。

**誤差**：d = QDQ(t) − t，t 是 FP32 張量，與 native errors 統計的定義相同。int 激活參數來自 calibration range。

**梯度**：由快取的 gY 經過 FP32 block 精確算出：
- gh = gY·Wd
- g_zg = gh ⊙ zu ⊙ SiLU′(zg)
- g_zu = gh ⊙ SiLU(zg)
- g_x 的 branch 版：g_zg·Wg 或 g_zu·Wu；total 版是兩者之和。X 是 post-attention RMSNorm 的輸出，只有 Gate、Up 兩個 consumer。

**統計**：每個 channel c，在 calibration 窗口與位置集合 P 上計算，n = 窗口數 × |P|。
- μ_c = Σd/n，var_c = Σd²/n − μ_c²
- G2_c = Σg²，GΣ_c = Σ_s(Σ_t g)²
- 變異項 = Σ_c G2_c·var_c；平均偏差項 = Σ_c GΣ_c·μ_c²；兩者相加就是 native 的 A。
- diag = Σ g²d²（逐元素，可以按位置相加）。
- P 有兩種：全部 128 個位置（與 native 相同），或 1–127（排除 position 0）。

**驗證**：全部位置的「變異項 + 平均偏差項」重現 native 的 `table.json` C，40 個 node × 格式中，median 相對差 1.2e-4、max 7.9e-4；branch 版對 `table_branch.json` 是 median 1.2e-4、max 1.6e-3。拆解本身是對的。

**block 輸出 Y**：e = Y_hat − Y_fp32，位置 0–126，用 gY 做同樣的拆解，另外算 MSE 與 position 0 的佔比。

**介入**：同一個候選的 Y_hat，分成兩個版本後重播下游：
- 只在 position 0 換成 Y_hat，其餘 FP32；
- 只在 position ≥1 換成 Y_hat。

用 calibration（0–9）與 tuning（10–29）窗口計算 summed CE 的變化。

**介入的範圍**：
- 4 層的 activation-only 單支候選（各 10 個）
- L27 的 weight-only 單支候選（8 個）

**正確性檢查**：L27 是最後一層，下游只有逐位置的 norm 與 LM head，所以兩部分的效應應該剛好相加。實測交互項是 0.00。

## 5. 建議

**節點層級的 BC**
- **保留變異項為主體。** 平均偏差項在 Qwen 上沒有提供額外預測力。這與 mbv2 depthwise int4 的情況不同：那裡每個 channel 的平均誤差是主要損傷。本研究不建議改動它。
- **不要排除 position 0。** 在節點層級排除後變差，例如 L27 的 wa 組從 0.84 降到 0.77。

**position 0 要單獨處理**
- 它的敏感度高度非線性，不能沿用逐元素一階權重。
- 可行做法是保持 gradient-based，把 position 0 的統計分開成一項，給它自己的敏感度；例如用 position 0 的 per-window 梯度與誤差另外估計，而不是和其他 127 個位置混在一起平均。
- 新項的權重不能用本研究的 tuning 結果來調，必須在新的窗口上預先登記後驗證。

**block 輸出 criterion**：排除 position 0 後排序可以到 0.887，但這會丟掉 L0 int4 這類真實損傷，不建議直接採用。

**範圍與樣本**
- 下一個驗證應該用新的 validation 窗口（例如 30–59），並包含 weight-only 組；先前 L27 weight-only 的 tuning 值主要由 position 0 的單一 token 主導。

## 7. 錯誤排序來自變異項還是平均偏差項（追加，事後）

- 少數 outlier channel 或全體。

- **沒有任何變體能大幅修正錯誤**，最好的淨效果只有 +21 到 +27 對，而且多半發生在 L2 的小差異配對：
  - 去掉 outlier channel 主要修正 L2 a（+19／−0）。p6e1 的變異項有 44–85% 落在 outlier channel，int 格式只有 ≤ 8%。
  - 逐元素 Σg²d² 修正 L2（+44），但弄壞 L27（−29）。
- **position 0 的誤差統計本身不是問題**：去掉它只有 +6／−0。去掉 position 0 的梯度則讓 L27 變差（−55）。

**錯誤配對的大小**（基準排錯的配對，依 |ΔS_tune| 分組）

| |ΔS_tune| | 錯 | 配對 | 錯誤率 |
|---|---:|---:|---:|
| 1–5 | 137 | 501 | 0.27 |
| 5–20 | 116 | 336 | 0.35 |
| 20–100 | 57 | 726 | 0.08 |
| > 100 | 102 | 1588 | 0.06 |

- **61% 是小差異配對。** |ΔS| ≤ 20 相當於每 token ≤ 0.008 nats，接近雜訊。
- **102 個大差異錯誤中，98 個兩邊都含 int4 激活。** 它們都是同一個問題的重複：在 L0、L2、L27，int4 放在 Gate 還是 Up 比較傷。

**這三個決策為什麼錯：position 0 的敏感度權重兩個方向都錯**

| 候選（activation int4） | 變異項 | position 0 梯度佔變異項 | 實際損傷 cal／tune | 其中 position 0 造成 cal／tune |
|---|---:|---:|---|---|
| L0 Gate | 1222 | 4.5% | 1208／990 | 80%／63% |
| L0 Up | 1305 | 4.5% | 178／619 | 21%／50% |
| L2 Gate | 3979 | 0.1% | 587／1260 | 41%／48% |
| L2 Up | 2779 | 0.3% | 1947／3795 | 78%／62% |
| L27 Gate | 4566 | 76.6% | 912／1776 | −2%／−3% |
| L27 Up | 4588 | 70.1% | 825／1651 | 0%／0% |

- **L0、L2：低估。** position 0 的梯度很小（g² 份量 0.1–4.5%），但 int4 大小的擾動讓 attention sink 產生很大的非線性損傷。二階、小擾動的 Fisher 權重看不到這種效應。
- **L27：高估。** position 0 的梯度很大，但 int 誤差幾乎不在 position 0（x tap 的 d² 佔比為 0）。變異項的形式是 Σ_c G2_c·σ²_c，把 position 0 的大梯度和其他位置的誤差在同一個 channel 裡相乘，造成跨位置混合；實際損傷約 0。
- **重新加權救不了。** 無論去掉 position 0、去掉 outlier channel、或改用逐元素形式，都修不好這三個決策。原因在敏感度的估法：position 0 的損傷不是 g² 能描述的。

**實務影響**
- 這些錯誤集中在 int4 激活。目前自動 knee 的 Gate／Up 激活是 p8e1／f16，所以對預設流程的影響有限；在激進 budget 下會變重要。

**建議**（需要在新窗口上預先登記驗證）
- 把 position 0 從變異項中分出來，成為一個單獨的項。
- 其他位置的項沿用現有的 G2·σ²，或改成逐元素 Σg²d²。
- position 0 的敏感度不能用 g²。可以考慮仍以 backward 為基礎的曲率估計，例如 FP32 與加入格式誤差後兩次 backward 的梯度差。

### 7.2 position 0 錯排的原因：梯度與誤差配錯，還是量化改動太大（追加，事後）

**配對檢查**（`variance.json`，節點層級的 int4 激活）
- 比較兩種形式中 position 0 的份量：
  - 變異項的乘積形式：position 0 的梯度能量 × 所有位置的誤差變異；
  - 逐元素 Σg²d²：只算 position 0 自己的 g²d²。

| 案例 | 乘積形式總值 | 其中 position 0 | 逐元素總值 | 其中 position 0 |
|---|---:|---:|---:|---:|
| L0 Gate | 1222 | 4.5% | 1324 | 4.2% |
| L0 Up | 1305 | 4.5% | 1417 | 4.2% |
| L2 Gate | 3979 | 0.1% | 3867 | 0.3% |
| L2 Up | 2779 | 0.3% | 4102 | 0.4% |
| L27 Gate | 4566 | 76.6% | 2661 | 21.0% |
| L27 Up | 4588 | 70.1% | 2310 | 3.1% |

**α 掃描**（`--stage scaling`，結果在 `scaling.json`、`scaling.md`）
- 誤差 e 乘上 α 後只放在 position 0（或只放在 position ≥1），重播下游，量 ΔL。
- 擬合：用三個最小的 α，在 calibration 上擬合 ΔL = a1·α + a2·α²，再外插到 α = 1。
- 梯度預測（calibration）：
  - 一階 F = Σ⟨gY, e⟩
  - Fisher 曲率 Q_dir = ½Σ_s(⟨gY, e⟩_s)²

| 案例 | 位置 | calibration ΔL（α = 1/16, 1/8, 1/4, 1/2, 1） | tuning ΔL（α = 1/2 → 1） | 實際／二次外插 | a1 ／ F | a2 ／ Q_dir |
|---|---|---|---|---:|---|---|
| L0 Gate | pos 0 | 1.2, 2.6, 6.7, 19.0, **964.8** | 22 → **627** | **16** | 15.8 ／ 17.9 | 44 ／ 46 |
| L0 Up | pos 0 | 0.4, 0.8, 1.9, 7.8, 37.3 | 4 → **311** | 2.2 | 4.6 ／ 6.0 | 13 ／ 17 |
| L2 Gate | pos 0 | 5.2, 12.3, 30.3, 56.0, 243.5 | 103 → 601 | 0.92 | 73.8 ／ 70.4 | 190 ／ 283 |
| L2 Up | pos 0 | 5.6, 13.1, 32.3, 58.9, **1518.0** | 108 → **2344** | **5.4** | 78.5 ／ 74.1 | 203 ／ 316 |
| L27 Gate | pos 0 | −5.0, −9.0, −14.7, −20.3, −22.7 | −49 → −57 | — | −86 ／ −89 | 109 ／ 414 |
| L27 Up | pos 0 | −0.2, −0.3, −0.2, 0.7, 3.3 | 0.3 → 4.6 | 0.37 | −4.0 ／ −4.4 | 13 ／ 17 |
| 其他位置（6 案例） | ≥1 | 從 α = 1/2 到 1 的指數 1.4–2.2 | — | 0.73–1.8 | — | Fisher 高估 1.3–16 倍 |

**結論**
- **L0、L2 的低估：量化改動太大，不是配錯。**
  - 兩種形式的 position 0 份量相同（0.1–4.5%），所以不是配錯。
  - 小擾動時，梯度的一階與 Fisher 曲率都和實際響應吻合：a1 對 F、a2 對 Q_dir 都在約 1.6 倍以內。
  - 到 int4 的完整大小時，L0 Gate 與 L2 Up 在 position 0 暴增：從 α = 1/2 到 1，增加 26–50 倍，是二次外插的 5–16 倍。tuning 窗口也一樣。L0 Up 在 calibration 上還算平滑，tuning 卻增加 72 倍。
  - 這是 attention sink 被推出局部二次範圍的門檻效應。
  - **為什麼 Gate／Up 會判斷反**：同一層的兩支，局部曲率幾乎相同（L2：190 對 203），差別只在哪一支的 int4 誤差跨過門檻。任何局部、梯度二階的準則都看不到這一點。
- **L27 的高估：配錯，加上響應是一階的。**
  - position 0 的響應沒有暴增，主要是一階而且是負的：a1 = −86，梯度預測 F = −89，誤差反而讓 position 0 的 loss 下降。二階的變異項永遠把它算成正的損傷。
  - 乘積形式又把 position 0 的大梯度和其他位置的誤差配在一起：佔 70–77%，逐元素只有 3–21%。改用逐元素後，L27 的 Gate／Up int4 順序就對了（2661 > 2310，實際 1776 > 1651）。
- **其他位置在二次範圍內。** 但 Fisher 曲率相對真實曲率的比例因層而異：L0 約 2.6–16 倍，L2 約 1.3–1.5 倍，L27 約 4.5–5.3 倍。這不影響同層內的排序，但跨層的尺度不一致可能影響 MILP 的位元分配。這點本研究沒有驗證。

**修正方向**（都仍以 backward 為基礎，需要預先登記、在新窗口驗證）

| 問題 | 方向 | 做法 |
|---|---|---|
| L0、L2：改動太大 | 在量化後的點再算一次梯度 | 梯形法 ΔL ≈ ½(g(0) + g(e))·e，只需在 position 0 加入量化誤差後多一次 backward；超出二次範圍時 g(e) 會變大，可以捕捉門檻效應 |
| L27：配錯與正負號 | 拆開 position 0 | position 0 用逐元素形式，並保留帶號的一階項；其他位置沿用現有統計 |

### 7.3 在量化後的點再算一次梯度：梯形法與 Simpson 的評估（追加，事後）

**方法**（`--stage trapezoid`，結果在 `trapezoid.json`、`trapezoid.md`）
- 對 6 個 int4 激活單支案例做下游 backward：
  - 梯形法：在 FP32 點和量化後的點各一次，ΔL ≈ ½(g(0) + g(e))·e；
  - Simpson：再加中點，ΔL ≈ (g(0) + 4g(e/2) + g(e))·e / 6。
- 誤差只放在 position 0、只放在 position ≥1、或全部位置。
- 梯度只用 calibration 窗口，和建表方式一致。
- 檢查：下游 backward 的 g(0) 和快取的 gY 最大相對差 ≤ 2.3e-4。

**評估結論**
- **在二次範圍內很準。** 其他位置與 L27 上，Simpson 落在實際值的 0.89–1.05 倍，梯形法 0.84–1.17 倍，遠比 Fisher 變異項準。
  - 它直接用帶號梯度和真實的逐元素誤差，沒有乘積形式的配錯，也保留正負號，所以 L27 的判斷修正了。
- **sink 暴增時只對一半。**
  - L2：排序對了，但量級高估 3–21 倍。sink 被破壞後，量化點上的梯度很大，loss 卻已經飽和。
  - L0 Gate：position 0 的實際損傷是 +965，梯形法與 Simpson 都估成負值。門檻是在 α = 1/2 到 1 之間的急遽跳升，只在 0、1/2、1 三個點取梯度抓不到。
- **三個判斷修正了兩個**（L2、L27），L0 仍錯。只有 3 個判斷，不具統計意義。
- **成本很高。**
  - 每個（節點，格式）都要在自己的量化點多做 1 次 backward（梯形法）或 2 次（Simpson）。
  - 完整表格是 196 節點 × 10 格式 × 10 窗口 ≈ 2 萬次 backward，現行只要 10 次；以 native 每次約 20–50 秒估算，需要上百小時。
  - 若只用在 int4 激活，約 196 × 10 ≈ 2000 次，仍然很貴。
  - 便宜的變體也有代價：每層同時套用所有節點的誤差，只做 1 次 backward。但這會混入節點間的交互作用，需要另外驗證。
- **L2 的量級失真會影響跨層分配。** L2 int4 的成本會被估成實際的 10 倍以上，接進 MILP 時會扭曲位元分配。

**建議**
- **目前不接入。** 對預設 knee 影響有限（Gate／Up 激活多為 p8e1／f16），成本卻高出約三個數量級。
- **若要繼續**：只在 int4 激活、而且 sink 明顯的層（L0–L3）用 Simpson；其他位置沿用現有統計。必須在新窗口上預先登記驗證，並檢查跨層尺度。
- **較便宜的做法**：在 int4 激活的候選上加一個「position 0 門檻檢查」，例如量化後的點上 position 0 的梯度範數突增時就標記。它只用來排除危險候選，不量化損傷。
