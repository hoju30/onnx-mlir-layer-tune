## 結論

**一階項在每一批 calibration 本身都很準，但它描述的偏好不能轉移到別的文本。問題主要不是公式，而是單一 expert 同資源候選之間的差異太小，10 個窗口量不準。**

| 問題 | 回答 |
|---|---|
| 1. 一階項在每批 calibration 本身是否準確？ | **是。** F+0.5B 和同批實測的方向一致率為 97.1–98.8%（中位數 98.1%；原 calibration C0 為 99.2%），組內 Spearman 0.98–0.99。BC 只有 41–54%，Spearman 約 0。A（近似本身不準）不成立。 |
| 2. 換 calibration 後，偏好與選擇是否穩定？ | **不穩定。**<br>• 任兩批之間，F+0.5B 的方向一致率平均只有 54.2%。<br>• 每個群組在 8 批中平均出現 3.7 種不同選擇，最常被選者只占 46%，63 個群組沒有一個 8 批一致。<br>• 各批的**實測** loss 本身也一樣不穩定：兩批之間方向一致 53.8%，每群組平均 3.8 種最佳候選。 |
| 3. BC 是否同樣不穩定？ | **BC 很穩定，但穩定不等於正確。**<br>• 兩批之間方向一致 96.4%，43/63 個群組 8 批都選同一個。<br>• 但 BC 和同批實測只一致約 50%，和 J 一致 48.8%。<br>• 它穩定是因為排序由量化誤差大小主導，而不是由文本決定。 |
| 4. 近似誤差與跨文本轉移各占多少？ | **幾乎全是轉移。**<br>• F+0.5B 和 J 方向不一致的 (批次, 配對) 中，近似錯誤（分數和該批實測不同）占全部格的 0.9%，轉移錯誤（分數符合該批實測、但實測和 J 不同）占 44.7%。<br>• 依 \|J 差\| 加權：0.7% 對 36.0%。<br>• 選擇層級：「分數選擇 − 該批實測最佳」在 J 上是 −6.9e-6 [−1.8e-5, −2.6e-7]，也就是分數偏離該批 truth 的部分反而略好。「該批實測最佳 − BC」是 −5.9e-6 [−2.7e-5, +1.7e-5]。 |
| 5. 覆蓋不足和錯誤是否相關？ | **在本輪的覆蓋範圍內看不到關聯。**<br>• 同一 expert 跨批的 Spearman（覆蓋 vs 不穩定或 J 損傷）：+0.06、−0.08、−0.16，Holm p 為 1.0、1.0、0.63。<br>• L15.E59 在 67–841 個 token 的各批中，主方案的 J 點估計都比 BC 好。<br>• 上一輪的大損失發生在只有 3 個 token 的 C0；本輪沒有覆蓋這麼低的 L15.E59。<br>• C（覆蓋不足造成不穩定）未獲支持，但極低覆蓋的情況沒有測到，仍是推測。 |
| 6. 下一步研究什麼？ | **資料代表性與樣本量，以及單點差異本身是否值得排序；不是估計公式。**<br>• 公式已經準（97–99%）。<br>• 批內一階差的 \|t\| 分布接近純雜訊（見事後分析）。<br>• 證據足以排除「公式錯」，但不足以說明增加資料就能改善選擇。 |

**主要終點** [預先登記]
- F+0.5B 選擇減同批 BC 選擇，在 J 上的 loss 差：**−1.28e-5 nat/token，95% CI [−3.19e-5, +6.98e-6]**。
- 計算方式：63 群組 × 8 批等權平均；10000 次雙向 bootstrap（重抽批次，並重抽 J 文章、依 validation/test 分層）。
- 點估計偏向一階方案，但區間含 0，未確認改善。
- 8 批中有 7 批的點估計為負。只有 8 批，批次部分的不確定性估計粗糙。

## 設計（`plan.json`、`plan.md`，在任何資料、分數或 loss 之前寫定）

**範圍**
- 9 個 expert、27 個投影、360 個 weight-only 候選、909 對同資源比較、63 個群組。
- activation FP32；原量化器與範圍；量化誤差 ΔW 只取決於 W。
- 每段文本用自己的 FP32 route，評估時固定該 route。

**資料不足的預登記修訂**（寫在 plan 內，在抽任何資料之前）
- 排除先前所有 OLMoE 資料後（含 D、V、H 整篇文章），validation 剩 18 篇、test 剩 27 篇，共 45 篇。J 16 篇加 calibration 40 篇共需 56 篇，不夠。
- 改由 WikiText-2 raw **train** 抽 8 批 calibration：從原 HF 來源（Salesforce/wikitext）下載，sha256 和 hub LFS 一致。本機的 validation/test 也和同一來源一致。
- J 仍按先前方式從 validation、test 各抽 8 篇。
- 原 calibration（validation 開頭 1280 token）的來源和組成都不同。新舊差異不單獨歸因於「換文本」或「增加多樣性」。

**資料**
- C1–C8：每批 5 篇 train 文章 × 2 個連續窗口，每批 1270 個預測 token，seed 18021。抽樣順序決定批次。
- J：16 篇 × 4 個窗口，seed 18011。
- 抽樣不依 route、分數或 loss；文章標題、offset、token hash 記在 `segments.json`、`data_freeze.json`。
- 註：C1 的「Adjustments / Penalties , Pts」是 WikiText 標題解析把表格段落當成文章，依預登記不重抽。

**分數**
- 每批重新估計 B = BC/1270 和 F = Σ_s〈g_s, Q(W)−W〉/1270（FP64 累加）。
- 方法：B、F、F+0.5B（主要）、F+B（敏感度）。
- 另有歷史參考：原 frozen BC 選擇、上一輪 frozen 選擇。

**順序**
- plan → 抽資料 → 擷取 C1–C8 路由 → 計分 → calibration truth → **凍結全部選擇** → 擷取 J 路由 → J truth → 分析。

**無觀測**：8 批全部觀測到 9 個 expert，沒有「無觀測」格。主要終點的「只算有觀測格」版本和主版本相同。

## 4. 跨文本轉移診斷 [預先登記]

以 J 平均差的方向為準，把 8 批 × 909 對的格分成三類：
- **正確**：分數方向和 J 相同。
- **近似錯誤**：分數方向和 J 不同，而且也和該批實測不同。
- **轉移錯誤**：分數方向和該批實測相同，但該批實測和 J 不同。

| 方法 | 正確 | 近似錯誤 | 轉移錯誤 | \|J\| 加權（正確/近似/轉移） | J 可判定的 241 對（正確/近似/轉移） |
|---|---:|---:|---:|---|---|
| BC | 48.8% | 27.6% | 23.6% | 69.9 / 16.7 / 13.4 | 65.0 / 23.5 / 11.5 |
| F | 54.2% | 1.3% | 44.6% | 60.7 / 3.0 / 36.3 | 62.6 / 2.5 / 34.9 |
| **F+0.5B** | 54.4% | 0.9% | 44.7% | 63.3 / 0.7 / 36.0 | 64.7 / 0.6 / 34.6 |
| F+B | 54.8% | 1.5% | 43.7% | 65.9 / 1.1 / 33.0 | 66.8 / 0.8 / 32.4 |
| 各批實測（上限參考） | 54.1% | 0 | 45.9% | 62.5 / 0 / 37.5 | 64.3 / 0 / 35.7 |

- 各批實測和 J 的方向一致率：47.7–58.9%（C0 為 61.4%）。
- J 本身有 241/909 對在未校正下可判定。純雜訊下約只會有 45 對，所以 J 確實有訊號。
- 一階方案的錯誤幾乎全是轉移錯誤，它已經貼近「該批實測」這個上限。
- BC 在 \|J\| 加權和 J 可判定的配對上，正確率和一階方案相當，甚至略高。一階方案的優勢主要在差異極小的配對。

## 6. 固定案例 [預先登記]

**L15.E17 Up int8 vs p8e1**：
- F 在 8/8 批都偏好 p8e1，各批實測也 8/8 同向，BC 8/8 相反。

  - J 差從 C2 的 +2.3e-4（CI 不含 0，較差）到 C4／C5 的 −7.5e-5／−8.0e-5（CI 不含 0，較好）。

- 8 批點估計都偏向主方案，和 token 數無明顯關係（o3 組內 Spearman −0.02）。

- 上一輪在 H 上的損失（C0 只有 3 個 token）本輪沒有重現；本輪最低是 67 個 token。

**L8.E33 三對**：

| a ｜ b | C1–C8 實測方向（a 較差/較好） | J [CI95] | D/V | C0／H |
|---|---|---|---|---|
| gate p8e1 ｜ up p8e1 | 3／5 | +6.5e-5 [−1.7e-6, +1.4e-4] | a 較好 | a 較差 |
| gate int6, up p8e1 ｜ gate p8e1, up int6 | 4／4 | −9.5e-5 [−1.75e-4, −1.8e-5] | a 較差 | a 較好 |
| gate int8, up p8e1 ｜ gate p8e1, up int8 | 5／3 | −6.7e-5 [−1.46e-4, +2.0e-6] | a 較差 | a 較好 |

- 分數在 C0–C8 每一批都和該批實測同向，忠實。
- 但實測本身在各批之間翻轉。J 和 C0、H 同向，和 D/V 相反；第二對的 J CI 不含 0。
- BC 在 8 批都固定給出和 D/V 相同的方向。
- 結論：**分數忠實，truth 隨文本改變**。上一輪把這三對算成「BC 正確被翻轉」，在 J 上反而有一對 BC 錯。

## 事後探索：批內可靠度能否預測轉移 [事後]

腳本 `run_olmoe_calibration_posthoc.py`，輸出 `posthoc_reliability.json`。在看過 J 結果後才加入。
- 方法：用每批 5 篇文章算每對候選一階差的 t 值（只用 calibration 資料），依慣用的 \|t\| 區間分組，再看各組方向和 J 一致的比例。
- 沒有調整任何區間。

| \|t\| | 格數 | 純雜訊下的預期比例（t, df=4） | 實際比例 | 一階方向和 J 一致 |
|---|---:|---:|---:|---:|
| < 1 | 4218 | 62.6% | 58.0% | 53.7% |
| 1–2 | 2111 | 25.8% | 29.0% | 54.9% |
| 2–3 | 673 | 7.6% | 9.3% | 53.9% |
| ≥ 3 | 270 | 4.0% | 3.7% | 57.0% |

- 批內 \|t\| 的分布接近全為 0 效應時的 t 分布。
- 批內看起來「可靠」的方向（\|t\| ≥ 3），和 J 一致的比例也只有 57%。
- 用實測差算 t 結果相同：54% 到 56%。
- [推論] 大多數同資源配對的真實平均差，遠小於 5 篇文章能分辨的程度。單批一階差主要反映抽樣變異。
- 只用批內變異過濾分數（例如依 t 縮減）在這種樣本量下幫助有限。要讓排序可轉移，需要的資料量可能接近 J 的規模（64 窗口在 241/909 對上有訊號）。這是待檢驗的假說。

## 已確立與未確定

**已確立**
- 一階項計算正確，在每批 calibration 上忠實反映實測：F+0.5B 為 97–99%，C0 逐位元重現上一輪。
- 換 calibration 後，F、F+0.5B、F+B 的配對方向與群組選擇都不穩定（兩批一致約 54%；每群組 3.7 種選擇）；各批**實測**最佳也同樣不穩定。
- BC 很穩定（96%），但在單點同資源比較上幾乎沒有排序能力（同批約 50%，J 48.8%）。
- 一階方案和 J 的分歧中，近似錯誤低於 1%，其餘都是轉移錯誤。
- L15.E17 Up int8/p8e1 的一階方向在 8 批和 J 上都穩定。
- L8.E33 三對的實測方向會隨文本翻轉；分數每批都忠實。
- 主要終點：−1.28e-5 [−3.19e-5, +6.98e-6]，未確認改善。

**未確定或只是推測**
- 一階方案在完整配置下是否有益：不能由單點結果推論。
- 加入 B 能改善轉移（F → F+0.5B → F+B 的平均損傷 1.0e-5 → 4.5e-6 → 1.2e-6）：事後觀察，不能據此調係數，需要新的預先登記和新確認資料。
- 「覆蓋不足造成錯誤」：本輪未支持，但沒有測到 3 個 token 這種極低覆蓋。
- 「增加 calibration 窗口能讓一階排序可轉移」：只由 J 的可判定配對數和事後 t 分析間接支持，尚未直接測試。
- train 和 validation/test 之間是否有系統差異：本設計無法和「換文本」分開。

## 對下一步的建議（假說，不在本輪執行）

1. **資料量**：預先登記一個測試，比較同一公式在 10 個窗口和更多窗口（例如 40 或 80 個）calibration 下的 J 選擇損傷。評估需要另一組新確認資料，例如未用過的 train 文章（validation/test 只剩 10 和 18 篇 ≥512 token）。
2. **單點差異是否值得排序**：同資源候選的單點差多半約 1e-5，比文章間的變異小。可以預先登記「只在差異達到可判定程度時才偏離 BC」之類的規則，並用新資料檢驗。
3. **估計公式**：目前證據不支持優先修改公式（近似錯誤 < 1%）。B 的權重是否該更大，只能作為事後假說另行預先登記。
