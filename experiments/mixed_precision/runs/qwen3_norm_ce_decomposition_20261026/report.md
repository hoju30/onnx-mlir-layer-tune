# Qwen3-0.6B L27 Down：一階評分的失敗來自 RMSNorm 還是 CE？

日期：2026-10-26。
- 腳本：`run_qwen3_norm_ce_decomposition.py`（sha256 `dde936c621b6…`）。
- 計畫：`plan.json`／`plan.md`（20:07:47 寫入，沒有 amendment）。
- 規格：`reports/qwen3_norm_ce_decomposition_prompt_20261026.md`。

**範圍**
- 只做 L27 Down；目標權重固定為 A 的 INT8。
- 背景 U／F／W、九種格式、完整 input／output QDQ，都與前輪 `runs/qwen3_conditional_signed_score_20261026` 完全相同：沿用同一個 Env，GEMM 一樣每批 8 個窗口。
- 只用 GPU LMReplay。
- 沒有修改正式 BC、搜尋、量化器、配置或 native。

**分數與分解**（每窗口一次 baseline autograd，同時取得 g_z 與 g_u；只經 final norm 與 head，沒有 STE）

| 項目 | 定義 |
|---|---|
| S_z | g_z·(z_f − z_0)，即前輪的分數 |
| S_u | g_u·(u_f − u_0)，候選先通過實際的 RMSNorm |
| R_norm | S_u − S_z，Norm 線性化的校正 |
| KL | KL(p_0 ‖ p_f)，CE 的全部高階餘項（實數下 D = S_u + KL） |
| eps_head | S_logit,64 − S_u |
| eps_CE | D − D_64 |

- 浮點殘差（eps_head、eps_CE）在同一份 FP32 logits 上以 float64 計算。
- 恆等式 D = S_z + R_norm + KL + eps_head + eps_CE 逐位置成立，誤差 ≤ 4.4e-14。
- **K2 = ½Var_p0(Δlogit)** 是 KL 在 logit 空間的二次部分。計畫中只把它登記為描述量，不是分數，也不進入選擇器。

**單位與資料**
- 所有數值都是相對同背景 f16 的 nat/token 貢獻，負值代表有利。
- C：原 10 個 calibration 窗口（1270 個 target）。
- H：前輪的 128 篇 × 2 窗口，**已經看過**。每個窗口用自身背景的 local 梯度，只作事後機制分析；方括號是文章 bootstrap 95% 區間，只作描述。

## 首頁

### 1. INT8 為何被判成最有利：誤判全在 Rest，原因是 CE 的 KL 餘項，不是 Norm

F 背景（U、W 幾乎相同，見後文）：

| 資料 | 位置 | D（真值） | S_z | S_u | R_norm | KL | eps_head／eps_CE |
|---|---|---|---|---|---|---|---|
| C | P0 | −0.0009 | −0.0014 | −0.0015 | −0.0001 | +0.0007 | < 1e-7 |
| C | **Rest** | **+0.3786** | −0.1437 | −0.1607 | −0.0170 | **+0.5394** | < 1e-7 |
| C | All | +0.3778 | −0.1451 | −0.1623 | −0.0172 | +0.5400 | −7e-8／+2e-8 |
| H | All | +0.3683 [+0.355, +0.382] | −0.1060 | −0.1295 | −0.0236（128/128 篇為負） | +0.4978（128/128 篇為正） | −5e-7／+2e-8 |

- **位置**：P0 幾乎沒有作用。INT8 在 P0 的擾動很小（|dz|/|z_0| ≈ 0.06）；在其他位置很大（|dz|/|z_0| ≈ 0.52，|du|/|u_0| ≈ 0.28），h 的 RMS 卻幾乎不變（+0.9%）。
- **分解**：
  - Norm 校正 R_norm 是負的，讓 S_u 比 S_z 更負。所以 Norm 線性化不是誤判的原因，反而使它稍微更糟。
  - 真正的落差 D − S_z = +0.52 幾乎全部是 KL（+0.54）。
  - 浮點殘差可以忽略，約 1e-7。
- **結論**：INT8 的一階項確實是負的，但它在其他位置的擾動大到 CE 的高階代價遠大於一階收益。單看任何 signed 一階項，INT8 都會被誤判成有利。

### 2. Posit6／4 的失敗與 Posit8 的成功是同一個規律，只是擾動大小不同

F 背景，C（H 數值在方括號，為 All）：

| 格式 | 位置 | D | S_z | S_u | R_norm | KL |
|---|---|---|---|---|---|---|
| p8e1 | P0 | −0.0114 | −0.0226 | −0.0188 | +0.0039 | +0.0074 |
| p8e1 | Rest | +0.0068 | +0.0028 | +0.0026 | −0.0003 | +0.0043 |
| p8e1 | **All** | −0.0045 [H −0.0102] | −0.0198 [−0.0258] | −0.0162 [−0.0224] | +0.0036 [+0.0034] | +0.0117 [+0.0122] |
| p6e1 | P0 | −0.0164 | −0.0995 | −0.0390 | **+0.0606** | +0.0225 |
| p6e1 | Rest | +0.0962 | +0.0120 | +0.0036 | −0.0084 | **+0.0925** |
| p6e1 | **All** | +0.0797 [H +0.0663] | −0.0875 [−0.1045] | −0.0353 [−0.0560] | +0.0521 [+0.0485] | +0.1151 [+0.1223] |
| p4e1 | P0 | −0.0191 | −0.1145 | −0.0425 | **+0.0720** | +0.0234 |
| p4e1 | Rest | +0.2704 | +0.0919 | +0.0626 | −0.0293 | **+0.2078** |
| p4e1 | **All** | +0.2514 [H +0.2330] | −0.0226 [−0.0321] | +0.0201 [−0.0034] | +0.0427 [+0.0287] | +0.2313 [+0.2364] |

所有 Posit 都同時受兩個分項影響：

**(a) P0：S_z 誇大 position 0 的好處，由 Norm 校正修回（R_norm > 0）**
- 校正量：p8e1 +0.004，p6e1 +0.061，p4e1 +0.072。
- 描述量：p6e1／p4e1 在 P0 幾乎失去整個輸出（|dz|/|z_0| = 0.94／1.00），h 的 RMS 變成原來的 3.2–3.4 倍（p8e1 為 1.4 倍）。在這麼大的尺度變化下，Norm 的線性化會失效。
- 輸出大值是否被 Posit 的 maxpos 截斷，是推測，本輪沒有驗證。
- 修正後，P0 剩下的 KL 只有 0.007–0.025。

**(b) Rest：KL 主導**
- KL：p8e1 +0.004，p6e1 +0.093，p4e1 +0.208。
- 這裡的 R_norm 小且為負：H 上 119–127 篇為負，與 KL 部分抵銷。

**Posit8 為何成功**
- 兩個餘項都小：R_norm +0.004，KL +0.012，都小於它在 P0 的一階收益（S_u −0.016）。
- Posit6／4 的 P0 一階收益被 S_z 誇大 3–5 倍；修正 Norm 之後，在 Rest 仍差一個 KL。

**INT8 是另一種情形**：P0 沒有 Norm 問題，失敗完全來自 Rest 的 KL。

**計算是否可信**
- 三個背景、C 與 H 的分項方向都一致。
- 對 Posit 的 P0 與 INT8 的 Rest，R_norm 與 KL 幾乎每篇文章都同號，所以不是少數文章造成的。
- 浮點殘差：eps_head ≤ 2e-5（p4e1），eps_CE ≤ 1e-7，相對分項可以忽略。

### 3. S_u 只部分改善方向與排序，選擇器仍選 INT8，仍缺 CE 的代價

| 背景 | 方向正確（C，8 個非 f16 格式）S_z → S_u | pair 正確（C，28 對）S_z → S_u | H 上凍結分數判對的 pair（27 個可判定）S_z → S_u | 選擇器（C 凍結） | H 上所選格式的 D |
|---|---|---|---|---|---|
| U | 6 → 7（修正 p6e1） | 19 → 22 | 18 → 21 | S_z int8 → S_u **int8**（margin 0.130） | +0.378 [+0.364, +0.392]，128/128 篇變差 |
| F | 5 → 6（修正 p4e1） | 16 → 19 | 15 → 18 | int8 → **int8**（0.127） | +0.368 [+0.355, +0.382] |
| W | 5 → 6（修正 p4e1） | 17 → 19 | 16 → 18 | int8 → **int8**（0.133） | +0.379 [+0.364, +0.393] |

**排序**
- S_u 在三個背景都多排對 2–3 對。
- H 上的方向判讀：p4e1 在三個背景都由錯變對；p6e1 只在 U 由錯變對，F 與 W 仍錯；int8 仍全錯；int8–p8e1 同位元對仍全錯；int6、int4 本來就對，仍對。

**選擇器**
- S_u 選擇器與 S_z 相同，都是 INT8，而且是規格定義的「嚴重有害」（H 平均 > 0.01，CI > 0）。
- 原 BC 選 f16（0）；H 上集合內實測最好的是 p8e1。
- 因為 F 與 U 的 S_u 都選 int8，「條件化是否改善選擇」在本輪無法分辨：F 真值下兩者差 0。

**p4e1 的修正很勉強**
- 凍結的 C 值是 S_u +0.020。但 H 上 local S_u 是 −0.0034 [−0.014, +0.007]（F）、+0.0030（W）、+0.0089（U），CI 都含 0。
- 也就是 Norm 校正只把 p4e1 推到 0 附近；它的真值 +0.23 幾乎全部是 KL。

**結論**：實際通過 RMSNorm 修正了 Posit 在 P0 的高估，但 KL 沒有被表示，所以仍會選錯，而且錯得很嚴重。

### 4. 下一步：值得研究 CE 餘項的低成本近似；Norm-aware 可以保留，但不足以單獨使用

**有支持的結論**（C 與 H 一致）
- 每個方向錯誤中，KL 都是最大的餘項，而且 INT8 的錯誤完全來自 KL。
- Norm 校正處理的是另一個問題：Posit 在 P0 的高估。
- 兩者都重要，但在決定選擇器時 KL 是瓶頸。
- 「仍無可用規律」不成立：規律很清楚，P0 尺度變化需要 Norm 校正，Rest 的大擾動需要 KL。

**描述量 K2**（預先登記，只作描述）
- 在所有格式上追蹤 KL：K2/KL 為 0.96–0.98（p8e1）、1.02–1.08（Posit6／4）、1.16–1.23（INT），格式間的順序與 KL 相同。
- 也就是 KL 大致是 logit 空間的二次量；大擾動時二次近似高估約 20%。

**事後算術**（未預先登記，只在 C 上、樣本內，不是本輪結論）
- 用 S_u + K2 排序時，三個背景的 8 個格式順序都與 C 真值完全相同，argmin 都是 p8e1。
- 但 K2 和 KL 一樣，要對每個候選做完整的 vocabulary head GEMM，**不是低成本**。

**待驗假說**（都未測試）
1. 不必對每個候選做完整 head 的 K2 近似，能否保留 K2 的格式順序。例如 ½Δu^T F_u Δu，其中 F_u = W^T(diag p_0 − p_0 p_0^T)W，只用 p_0 的 top-k 詞或低秩分解。
2. S_u 加上這個近似後，方向、pair 與選擇器能否在全新文章上成立。
3. 這種組合在 L27 以外的層是否可行：其他層的後綴有 QDQ，需要另外設計。

**最小下一個實驗**
- 在 C 上預先固定一種 top-k（或低秩）K2 近似與它的 k，與精確 K2／KL 比較格式順序與成本。
- 凍結後，抽全新文章驗證 S_u + 近似 K2 的方向、pair 與選擇器。
- 仍然只做 L27，不改正式 BC。

## 控制（C、H 全部通過）

**LM head 與 final norm**
- LM head 是 `Linear`，沒有 bias，與 embedding 共享權重，不在搜尋或量化之列。
- lm_head 與 final norm 都沒有 hook。forward 中沒有 softcap 或 temperature，config 沒有 final_logit_softcapping。
- final norm 是 Qwen3RMSNorm，eps 1e-6；transformers 4.57.6。

**與完整 forward 及前輪的一致性**
- closure 與完整 forward 的差：C 為 3 背景 × 9 格式，H 為每個 chunk 的 f16，都是 0。
- 重現前輪 C 的凍結 S_z 與真值：每 token 差 5.6e-17。S_z 選擇器同為 int8／int8／int8。
- 重現前輪 H 的逐位置 CE：27 組全部相同，差 0。

**梯度鏈**：g_z 與「g_u 經 Norm VJP」的相對差為 0；與 float64 解析 RMSNorm Jacobian 的相對差 ≤ 2.2e-7。

**恆等式與基準**
- D_64 = S_logit,64 + KL_64，以及完整的五項重建，逐位置誤差 ≤ 4.4e-14。
- KL 最小值 0，沒有負值。
- f16 的所有差值與 KL 都精確為 0；位置 127 的 g_z、g_u、S 都為 0。
- P0 + Rest = All：總和誤差 ≤ 3.6e-12。

**背景與環境**：三個背景的目標權重都是 INT8；TF32 關閉、deterministic。

**浮點旗標（預先定義，只報告不判失敗）**
- 只有 H 的 F／fp32 的 Rest 與 All 觸發：eps_head + eps_CE ≈ −8e-8 nat/token，而 D 只有 +6.6e-7 與 −2.4e-6。
- 也就是只有 fp32 這種 D 本身極小的格式，浮點殘差才佔可見比例。
- 門檻以 summed CE 定義（1e-3 + 1%|D|）。H 有 32512 個 target，所以這個門檻換算到每 token 比 C 嚴格。
