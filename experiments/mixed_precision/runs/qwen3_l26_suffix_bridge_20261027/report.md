# Qwen3-0.6B L26 Down：block27 後綴重播加 top-256 評分

日期：2026-10-27。
- 腳本：`run_qwen3_l26_suffix_bridge.py`。
- 計畫：`plan.json`／`plan.md`（01:41:13 寫入，沒有 amendment）。
- 規格：`reports/qwen3_l26_suffix_bridge_prompt_20261027.md`。

**範圍**
- 目標是 `/model/model/layers.26/mlp/down_proj/MatMul`，權重固定為 A 的 **INT6**（由 FP32 權重經既有量化器量化一次）。
- 背景只有兩個：F（主要，其他 195 個投影依 A，包含 block27 的權重與 activation QDQ）、U（其他投影全 FP32）。
- 九種 activation 格式，同時套用在 input 與 output。
- k = 256 固定。只用 GPU LMReplay。
- 沒有修改正式 BC、A、量化器、MILP／knee 或 native。

**每個候選都走過真實的 block27**

```
z26 = Q_y(linear(Q_x(x26), W26q))
h27 = r26 + z26
u   = final_norm(block27(h27, 同批的 kwargs))
logits = LM_head(u)
```

- block27 使用同一批 baseline forward 捕捉的 kwargs：attention mask、position ids／embeddings、cache position；use_cache=False，沒有 cache 物件。
- block27 的背景 QDQ 都在作用。

**分數**
- g_u 只經 head：u_0 設為 leaf，每個窗口一次 backward。
- S_u = g_u·(u_f − u_0)。
- Khat256 與 P256 = S_u + Khat256 完全沿用前輪的實作與精度。

**本輪的定位**
- 這驗證的是「經真實後綴傳播後，head 的二次近似能否壓縮候選評分」，**不是**免重播的 L26 局部 criterion。
- P0／Rest 只指最終 CE 的位置，不代表源位置。

**資料與單位**
- C：原 10 個 calibration 窗口，只用來建立分數並凍結選擇器。
- N：新抽 128 篇文章 × 2 窗口，只量真值。
- 數值是相對同背景 f16 的 nat/token 貢獻，負值代表有利。
- N 的區間是文章 bootstrap 20000 次的 95% CI（seed 26102713）。

**主要比較**

**原因判讀**

### 3. 把 block27 算進去後，P256 只比直接 CE 快 6%（含 prefix 3%），顯存少 0.09 GB

測量條件：F 背景、C 的 10 個窗口（batch 8 + 2）、7 個非 f16 候選（f16 在各方法都重用 baseline）。每個方法每個候選都包含 target QDQ／GEMM、block27 與 final norm。5 次 warmup + 20 次計時，取 median（p90 與 median 相差 < 0.2%）；RTX 3060。

| 方法 | baseline | 候選熱增量（7 個） | baseline + 候選 | 再加 prefix 0.625 s | 峰值 VRAM 增量 |
|---|---|---|---|---|---|
| 後綴 + S_u | 0.127 s | 0.101 s | 0.228 s | 0.853 s | 0.32 GB |
| **後綴 + S_u + Khat256** | 0.427 s | **0.108 s** | **0.535 s** | **1.160 s** | 1.80 GB |

| 後綴 + 直接 head／CE | 0（重用 prefix CE） | 0.570 s | 0.570 s | 1.195 s | 1.89 GB |

**與直接 CE 比較**
- baseline + 候選：0.535 對 0.570 s，省 6%。

- 損益平衡點：baseline 前處理 0.427 s ÷ 每候選節省（81.5 − 15.4 ms）≈ 6.5 個候選。本輪 7 個候選剛好越過。

**與完整 K2 比較**：省 40%；含 prefix 省 23%。

### 4. 下一步：不建議把這個近似再往前一層推；先處理 calibration 選擇的轉移

**本輪支持的結論**（L26、GPU）
- 經真實 block27 傳播後，head 的 top-256 二次項仍完整保留候選順序，與完整 K2、C 實測相同，修正了一階 S_u 的嚴重錯誤（int6 +0.066）。
- 但時間幾乎不省，因為主要成本來自每候選的 block27。
- 而且最終選擇錯在 calibration 資料：用 C 實測真值直接挑也一樣錯。

**為什麼不往前一層**
- 每往前一層，每候選都要多重播一個 block，直接 CE 與 P256 的差距只會更小。
- 要有時間收益，必須先有不必逐候選重播的方法，而本輪沒有提供這個方法。

**待驗的最小下一步**（都未執行）
1. **calibration 轉移**：同一個 selector（甚至直接 CE）在 10 個窗口上挑的格式，換到新文章是否穩定。可以預先登記用更多或不同來源的 calibration 窗口重做 L26 F 的 C 選擇，或加上依窗口間變異的「保留 f16」規則；然後凍結並在新文章上驗證。這個問題與近似無關。
2. 若仍要追求跨層低成本，需要另外研究免逐候選重播的後綴近似。本輪沒有證據支持任何具體形式。

## 控制（全部通過）

**重播與完整 forward 的一致性**
- C 上 2 背景 × 9 格式，三項的最大差都是 **0**（逐位元相同）：block27 輸入（= r26 + z26）、final u、逐位置 CE。
- N 上每個 chunk 的 f16 重播與完整 forward 差 0。

**與前輪的一致性**：F／f16 在 C 上的逐位置 CE 重現前輪 F／f16，差 0；切換 F → U → F 後也重現，差 0。

**權重、activation 與 hook**
- 目標權重是快取的 INT6，而且不等於 FP32。
- 背景權重與 activation map 都與配置相符，F 與 U 背景都檢查過，F 重設後再檢查一次。
- LMReplay 在目標上看到的 activation 是 fp32，也就是 no-op。

| 位置 | hook 數（pre, post） | 說明 |
|---|---|---|
| 目標 | 2, 2 | LMReplay no-op + 本輪各一 |
| block27 pre | 1 | |
| final norm | 0, 1 | 只做捕捉 |
| lm_head | 0, 0 | |
| 其他 195 個投影 | 1, 1 | |

**kwargs**：attention mask [1,1,128,128]、position ids [1,128]、cache position [128]、position embeddings 2 × [1,128,128]、past_key_values None、use_cache False。每一批各自捕捉。

**head 與梯度**
- LM head 是無 bias、tied、未量化的 `Linear`，沒有 softcap 或 temperature。
- g_u 與 float64 的 W^T(p − onehot) 相對差 1.9e-5（F 背景，窗口 0 與 9）。
