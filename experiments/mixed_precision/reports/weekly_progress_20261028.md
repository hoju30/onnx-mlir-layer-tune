# 週進度報告：BC 混合精度搜尋的更新成本、誤差機制與泛化驗證

> 本週主講範圍已依使用者選擇收斂為兩個方向，請使用[六頁主講版：GEMQ 與 activation spikes](weekly_progress_20261028_two_topics.md)。本檔保留為完整實驗備查與口稿來源。

報告日：2026-10-28。涵蓋實驗：2026-10-22–2026-10-27。

建議主講 10 頁、約 15–18 分鐘；每頁保留一個問題、一組核心數據與一個結論。下方「口稿」可直接使用或縮短。附錄供追問使用。

**整份報告的主旨**

本週沿著「更新統計能否改善配置 → spike／Posit 誤排的來源 → 是否需要一階與輸出端資訊 → 原 BC 排名可靠性」做驗證。局部改善與機制證據已取得，但通用修正尚未通過跨層、新文章與完整配置的檢驗；目前保留原 BC 作為正式預設。

**數字閱讀規則**

- 品質主要用 NLL（nat/token），方法−基準的差值小於 0 代表改善。PPL 是平均 NLL 取 exp。
- 不同實驗使用不同的新文章、配置或資源點；不同列的絕對 NLL／PPL 不直接比較，也不把收益相加。
- BC 分數是排序 proxy，不要求絕對數值等於 NLL；判讀同時看排序與選錯格式的實際代價。
- 「未確認改善」表示區間仍允許多種方向，不代表已證明完全無效或等效。
- 配對數不等於獨立樣本數。信賴區間以文章重抽樣；同一層／格式對在多組校準重複出現，不能當獨立重現。
- 每頁標出 GPU QDQ、native 推論、局部介入或完整配置，避免把不同範圍的結果混用。

## 第 1 頁｜本週研究問題：增加哪種資訊，才值得增加離線成本？

**投影片放這些**

研究目標：維持 compiler-oriented、低 offline 成本的混合精度搜尋，驗證 BC 的額外資訊是否能改善實際格式選擇。

| 方向 | 問題 | 本週觀察 |
|---|---|---|
| 量化後更新 proxy | 在量化狀態重算 sensitivity／error，是否值得？ | 部分配置有小收益，額外成本高，未形成預設方案 |
| Spike／Posit 誤差機制 | channel 彙整是否漏掉位置、偏差或大擾動資訊？ | 找到不同局部失配，修正沒有穩定改善完整配置 |
| 一階與輸出端評分 | 補方向資訊能否跨層改善？ | L27 有成功案例，L26 與跨層確認未支持通用化 |
| 原 BC 的可靠性 | BC 是不穩定，還是穩定地排錯？ | 新測三層的同 bit 排名穩定且表現良好 |

**口稿**

「這週主要在確認：我們要多算什麼資訊，才真的能讓混合精度選擇變好，而且值得增加離線時間。我先測量化後更新統計，再追 spike 與 Posit 的誤排，接著測一階和輸出端評分能不能跨層使用。最後回到原 BC 做獨立對照，確認哪些問題是局部案例，哪些才可能影響一般搜尋。」

**轉場**：先看最直接的方法——在目前量化配置下更新一次統計。

## 第 2 頁｜OLMoE：更新 proxy 有小收益，成本效益尚不足

**投影片放這些**

條件：OLMoE dynamic route、固定資源上限、GPU FP32＋QDQ；沿用 BC 公式，更新統計後重新選配置，不訓練 router。

| 實驗 | 相對 static BC 的 NLL 差 | 區間／判讀 | 額外成本 |
|---|---:|---|---|
| Aggressive 點完整 refresh，新 600 篇確認 | **−0.00121** | 95% CI [−0.00219, −0.00024]，確認小幅改善 | 前輪單次量測約 **+108 秒**；原流程約 104 秒 |
| Aggressive 點，只更新 ≤4-bit 節點的 sensitivity | **−0.00173** | 95% CI [−0.00264, −0.00080]，確認改善；相對完整更新的預定非劣性成立 | **+39.9 秒**，同輪完整更新 80.6 秒 |
| 正常 knee，只更新 weight sensitivity | −0.00021 | 校正 CI [−0.00098, +0.00056]，未確認改善 | 更新階段中位數 **+66.1 秒** |

- Aggressive 點：PPL **19.876 → 19.852**，約降低 0.12%；量化損傷約減少 3.6%。
- ≤4-bit sensitivity 的改善到了正常 knee 沒有重現：NLL 差 **+0.000001**，95% CI [−0.00063, +0.00065]。不能把 aggressive 的正面結果推廣為預設策略。
- 正常 knee 的部分更新研究涵蓋 sensitivity-only、error-only、低 bit 子集及 weight-only sensitivity；尚未確認穩定收益。
- 上表各輪的配置、資料與計時範圍不同，不能用來估計精確的跨方法加速比；39.9 對 80.6 秒則是同輪比較。
- 具體更新版本與固定條件見附錄 F；這些是重建成本表後重搜格式，沒有更新模型參數。
- 決策：保留為研究結果，沒有加入正式 pipeline 預設。

**口稿**

「完整更新在較激進的資源點有小幅改善，但額外成本接近原流程本身。接著只更新低 bit 節點的敏感度，在另一批新文章也確認有效，額外時間從同輪完整更新的八十一秒減到四十秒。不過這個成功到了正常 knee 沒有重現。之後也測了擴大到五 bit、只更新 error、只更新 weight sensitivity，都沒有取得穩定的 knee 收益。因此目前沒有把更新設成預設步驟。」

## 第 3 頁｜Spike：保留更細的位置資訊，沒有穩定改善格式選擇

**投影片放這些**

假說：spike 發生位置的敏感度可能與 channel 平均不同。測試兩種改法：

- Spike／非 spike 分組計算統計。
- 將變異項的「channel 平均敏感度 × 誤差平方和」改成同位置的 g² 與中心化誤差平方相乘。

Qwen3-0.6B：28 層 Down input，各層單獨量化，其他部分 FP32；GPU QDQ、新 128 篇文章。

| 評分 | 可判定同 bit 配對排對數 | 修正原 BC 誤排 |
|---|---:|---:|
| 原 BC | **74／78** | — |
| Spike 分組 | **74／78** | 0 |
| 同位置配對 | **74／78** | 0 |

原共有 84 對，6 對真值未定；三種方法共同排錯的 4 對集中在 L2／L27。

OLMoE 完整配置也測過同位置配對：

| 資源點 | 新評分−原 BC 的 NLL 差 | 95% CI |
|---|---:|---|
| 正常 knee | −0.000341 | [−0.00100, +0.000308] |
| Aggressive | −0.000207 | [−0.00101, +0.000609] |

兩者各用新 600 篇文章，均未確認完整配置改善。

**口稿**

「接下來我測的是，BC 是否因為把位置平均掉，沒有對準真正發生 spike 的地方。我分別試了 spike 分組和同位置配對。在 Qwen 的二十八層單點比較中，三種方法都排對七十八對中的七十四對，剩下四個錯誤沒有被修掉。OLMoE 也做了兩個資源點的完整配置比較，但效果區間都跨零。所以粒度變細可以改變分數，卻不保證改變有用的排名。」

來源：[Qwen3 全層單點比較](../runs/qwen3_down_spike_diag_20261023/report.md)、[OLMoE knee](../runs/olmoe_pair_knee_ab_20261023/report.md)、[OLMoE aggressive](../runs/olmoe_pair_aggressive_ab_20261023/report.md)。

## 第 4 頁｜誤排機制：不同層、不同 bit，缺的資訊不相同

**投影片放這些**

把真實量化誤差拆成：e = b + r，其中 b 是每 channel 的平均誤差，r 是剩餘誤差。以下為原校準窗口上的局部機制診斷，不是完整配置的收益。

| 案例 | 觀察 | 意義 |
|---|---|---|
| L27 Posit4 平均項 | 原 BC 平均項中，跨位置乘積項約占 **78%** | 此末層後續運算逐位置獨立；這些聚合交叉項不能直接當成真實跨位置曲率 |
| L27 4-bit 完整誤差 | INT4 損傷 **0.4605**，Posit4 **0.2552**；但平均偏移本身仍是 Posit4 略差 | 只修平均項，不能代表完整誤差已排對 |
| L27 6-bit 剩餘誤差 | 原變異項與真曲率排序不同；位置配對不足是線索 | 局部二階 proxy 確實可能失配 |
| L2 Posit6 的分解 | 平均部分 **2.647**、剩餘部分 **3.859**，完整只有 **0.052**；非加性約 **−6.454** | 人工拆開的誤差分量在真實模型中有強烈抵消，不能把分開損傷直接相加 |

單位：nat/token。這些實驗只改 Down input，權重、其他 activation 與 Down output 都保持 FP32。

**這頁結論**：已找到具體局部失配，但尚未找到可跨層使用的單一修正。

**口稿**

「這裡的進展是，把『Posit 不準』拆成比較具體的機制。L27 的平均項有跨位置聚合的高估，但四 bit 的完整排序還牽涉剩餘誤差；六 bit 又有位置配對問題。L2 更不同，平均和剩餘分量分開施加時都很傷，但一起施加會互相抵消。因此不能用一個結論說全部都是 bias、全部都是 variance，或全部只要補一階。」

來源：[平均項機制](../runs/qwen3_posit_mean_bias_20261025/report.md)、[變異項機制](../runs/qwen3_posit_variance_diagnostic_20261025/report.md)。平均項曾有狹窄範圍的正面驗證，見附錄 B，不能說所有局部修正都完全失敗。

## 第 5 頁｜完整 native pipeline：局部修正尚未轉成整體收益

**投影片放這些**

Qwen3-0.6B，新 128 篇文章，完整配置由 onnx-mlir 編譯與評估。

候選 E：spike 誤差分解，加量化端點的平方梯度；新統計在 GPU 計算，因此是混合建表與 native 推論，非新統計已 compiler-native。

| 比較 | Native NLL 差 | 預先指定的判讀 |
|---|---:|---|
| **相同兩個資源上限：E−原 BC** | **+0.0071** | 校正 CI [+0.0021, +0.0122]，**變差** |
| 各自自動 knee：E−原 BC | +0.0031 | 校正 CI [−0.0023, +0.0085]，未定；E 的 weight bytes 另多 0.16% |
| Aggressive 點：E−原 BC | −0.0088 | raw CI 不含 0，但 Holm p = **0.052**，未通過指定校正 |

- 同上限 PPL：**56.20 → 56.60**。
- E 修正了 L2 input 的 4-bit 選擇，卻破壞 6-bit；同上限下，有無端點更新的兩個候選甚至選到相同配置。
- L2 的正式 activation 成本還有 output 項，局部 input 修正沒有讓 L2 的最終格式改變。
- 決策：不整合 E，保留原 BC。

**口稿**

「這頁是實際 pipeline 的驗證。我們不能只看某個 input 的分數修好，就認為整個模型會改善。新候選在相同資源上限下，native PPL 從五十六點二變成五十六點六，確認變差。較激進的點雖有改善跡象，但沒有通過預先指定的校正。這次也看到正式選擇同時受 input、output 和全模型預算影響，所以局部機制成立，仍必須經過完整配置驗證。」

來源：[spike 端點完整 pipeline](../runs/qwen3_spike_endpoint_pipeline_20261026/report.md)。

## 第 6 頁｜L27：原 BC 確實漏掉一個較好的 native 配置

**投影片放這些**

固定原 BC knee 配置，只把 **L27 Down activation：FP16 → Posit8**；input／output 一起改，目標權重仍 INT8。

| 證據 | 結果 | 範圍 |
|---|---|---|
| 10/24 native 獨立確認 | NLL **−0.00868**，95% CI [−0.01179, −0.00555] | 新 128 篇文章，固定兩配置 |
| 資源 proxy | 搜尋範圍總 BOPs **降低 0.814%**，weight bytes 不變 | 非實測 kernel latency |
| 10/26 輸出端 S＋Khat256 選格式 | 選 Posit8；F 背景 NLL **−0.00933**，CI [−0.01137, −0.00727] | 另一批新 128 篇文章，GPU QDQ |
| 只用一階 S | 選 INT8；F 背景 NLL **+0.3763** | 單獨一階會嚴重誤選 |

S 保留有正負號的方向資訊；Khat256 近似輸出 CE 的二次代價。它不是全模型 Hessian，也不是直接在原 BC 上加 S。

成本限制：prefix 已備妥時，七個候選的 S＋Khat256 合計 **0.456 秒**，直接候選 head＋CE **0.558 秒**，只省約 18%；不代表完整建表快 18%。

**口稿**

「雖然通用修正沒有成功，但 L27 是一個確認過的真實案例。只把它從 FP16 改成 Posit8，在 native 新文章上品質更好，BOPs proxy 也更低。後來用輸出端一階加二次項，也能選到這個格式。不過單獨用一階會選成很差的 INT8，所以方向與有限擾動代價都要看。這提供了機制線索，還不代表已經有通用、低成本的替代 criterion。」

來源：[L27 native 確認](../runs/qwen3_l27_native_confirm_20261024/report.md)、[L27 top-256 評分](../runs/qwen3_topk_ce_curvature_20261026/report.md)。兩列品質數字來自不同批文章，不能合併成同一個效果估計。

## 第 7 頁｜L26：校準排序很準，也可能無法轉移到新文章

**投影片放這些**

L26 Down，權重固定 INT6；其他投影依原 knee 量化。每個候選實際通過 block27，再做輸出端評分。

| 指標 | 結果 |
|---|---|
| 校準 C：P256 對完整實測的格式配對排序 | **28／28 相同** |
| 校準 C：P256、完整二次參考、直接實測 loss 的選擇 | 全部選 **INT8** |
| C 的 INT8 相對 FP16 損傷 | **−0.00090** |
| 新文章 N 的 INT8 相對 FP16 損傷 | **+0.00959**，CI [+0.00784, +0.01143] |

因此，這個選錯不能只歸因於 top-256 近似：直接用校準實測 loss 選，也會犯相同錯誤。

補查文章覆蓋（另批實驗、固定 1280 tokens）：

- 單篇 10 窗口改成 10 篇各 1 窗口，平均選擇後果改善約 **0.0004**。
- 但各組平均仍比維持 FP16 差；留一窗口的改選率反而增加。
- 因此僅換成多文章校準，沒有完整解決問題。

**口稿**

「我把 L27 的方法往前移到 L26，保留真實的後續 block。結果在校準集上，二十八個格式配對都排對，甚至直接量 loss 也選同一個 INT8；但換到新文章，INT8 反而有害。這說明這個案例的瓶頸包含校準排名的轉移，不能只繼續提高 proxy 對校準 loss 的擬合。增加文章覆蓋稍微減輕平均傷害，但還沒有讓選擇穩定地勝過原本 FP16。」

來源：[L26 suffix bridge](../runs/qwen3_l26_suffix_bridge_20261027/report.md)、[L26 校準覆蓋](../runs/qwen3_l26_calib_coverage_20261027/report.md)。

## 第 8 頁｜一階跨層確認：沒有證據支持普遍加入

**投影片放這些**

事先指定 L7／L15／L23 Down；目標權重均 INT6，兩種其他投影背景（FP32／原 knee），三組各十篇新校準文章，再用新 128 篇文章驗證。

## 第 9 頁｜原 BC 獨立對照：局部排序可以穩定且正確

**投影片放這些**

L7／L15／L23 Down；**所有權重與其他 activation 全 FP32**，只量化目標 input／output。使用原 native BC 統計與固定 ranges，GPU QDQ 量測損傷。

- 三組各十篇新校準文章，各做 **5,000 次文章重抽樣**，重新聚合 BC。
- 凍結排名後，以 **128 篇新文章、256 個窗口**驗證。

| 範圍 | 排對 | 排錯 | 真值未定 |
|---|---:|---:|---:|
| 同 bit INT／Posit | **27** | **0** | 0 |
| 全部格式配對 | **219** | **3** | 30 |

- 同 bit 排名在重抽樣中均未翻轉；27 個判讀只有 **9 個不同配對真值**。
- L15 8-bit 的 CI 接近 0；附報 sign-flip p = **0.05030**，證據較弱。
- 3 個錯誤均為同一對 **L7 FP16／BF16**，在三組校準重複出現；實測差約 **0.000017 nat/token**。
- 5 個低穩定性判讀：2 個排對、3 個真值未定；尚無證據支持新增穩定性門檻。

**口稿**

「最後我直接回到原 BC，因為前面的輸出端評分結果不能代替 BC 本身的驗證。這次在乾淨的 FP32 背景下，同 bit 排名穩定，而且依預定規則全部與新文章方向一致。這讓我們更清楚：不能概括說 BC 的局部排序都不好。不過這輪目標權重也是 FP32，和前一頁的 INT6 不同，所以還不能推廣到實際完整混合精度配置。」

來源：[原 BC 排名可靠性](../runs/qwen_bc_rank_reliability_20261027/report.md)。原 C0 成本表重建最大相對誤差 2.0×10⁻¹⁶，控制檢查通過；這只是實作重現，不是精度保證。

## 第 10 頁｜本週結論與後續研究

**投影片放這些**

| 已建立的證據 | 目前還不能宣稱 |
|---|---|
| 原 BC 在部分 FP32 背景的局部同 bit 排序良好 | BC 已適用所有量化背景／完整配置 |
| L27 有 native 品質與 BOPs proxy 同時改善的配置 | 已有跨層通用、自動識別的修正規則 |
| 局部失配包括位置聚合、誤差分量抵消、有限幅度與方向效應 | 所有誤排都有相同原因 |
| 少量校準資料上的精確 loss 排名也可能無法轉移 | 只要把 criterion 擬合得更像校準 loss 就能改善 |
| Refresh、細粒度修正、一階的通用收益未被充分支持 | 應把這些額外成本加入正式預設 |

**目前決策**：保留原 BC 與現有搜尋預設；本週變體維持獨立研究分支。

**下一步規劃，尚未執行**：

1. 先彙整既有單點／背景／完整配置證據，避免重做已完成的前綴量化實驗。
2. 鎖定實際固定資源搜尋中會競爭的**跨 bit 候選與配置改動**，量化誤排是否真的造成可重現的 NLL 代價。
3. 只有確認影響足夠大，再針對該情境預登記最小的重新評分方案，連同 offline 增量及 native 效果驗證；不用目前這批 N 選規則。

**口稿**

「這週的成果，是把原本籠統的 criterion 不準，拆成可區分的問題。我們有局部機制、有 L27 的 native 正面案例，也完成了沒有通過的跨層與完整配置驗證。目前沒有足夠證據替換原 BC。下一步會更靠近實際搜尋決策，先確認哪些排名錯誤真的改變資源分配和最終品質，再決定在哪些情境值得多算，而不是對所有層一律增加成本。」

## 附錄 A｜Router fine-tuning：品質收益明確，但屬訓練擴充

固定 q0 的量化格式，只訓練 router 20 步；新 600 篇文章，GPU QDQ。

| 項目 | 結果 |
|---|---|
| q0＋FT − q0 | **−0.08243**，CI [−0.08556, −0.07925] |
| PPL | **19.819 → 18.251** |
| 額外 offline 時間 | **342.6 秒**，單次量測 |
| 相對原始 FP32 | NLL 還低 **0.04807** |

可以說：訓練 router 後，在這批新 WikiText 文章上有明顯收益。

不能把全部收益歸給 BC，也不能已斷定都是量化修復。原實驗沒有 FP32＋相同 FT 的對照，也沒有非 WikiText 評估，未能拆開量化修復與文本適應。考量目前以編譯器和低離線成本為主，本週將它放在附錄，未整合預設。

來源：[router-only fine-tuning](../runs/olmoe_router_ft_20261022/report.md)。

## 附錄 B｜平均項不是完全沒改善，但正面證據的範圍很窄

U_token 的實驗保留同 token 內的梯度耦合，去除跨位置平方聚合。它測的是人工平均偏移 x＋αμ，並非完整 INT／Posit QDQ。

- Even selector 在 84 個配對中只改 2 對：L24 4-bit、L27 6-bit，兩對都修正。
- 排除已知 L27 後，even 的收益全來自 L24 那一對。
- Signed selector 的主要收益集中在 L9 4-bit；完整配置收益沒有在此實驗測量。

因此，應說「有局部機制與有限的正面驗證，尚未形成通用 pipeline 改善」，不要說「所有 spike／bias 實驗都完全失敗」。

來源：[U_token 跨層與新文本驗證](../runs/qwen3_mean_u_token_validation_20261025/report.md)。

Qwen3 Down activation，27 層 × 3 同 bit 配對；目標權重與後綴保持 FP32，比較前綴 FP32／前綴按 A 量化，GPU QDQ，新 128 篇文章。

| 指標 | 結果 |

這輪不是整個後綴也量化的完整 knee 背景，也不是測所有跨 bit 候選。但它已反對「前層量化普遍導致同 bit 排名反轉」的說法，不應原封不動列為尚未執行的下一步。

| 實驗 | 目標權重 | 改動的 activation | 背景 | 評估層級／後端 |

## 附錄 E｜可直接回答的問題

**這週到底有沒有找到 criterion 的不足？**

有找到局部、可檢查的不足，包括 L27 的跨位置聚合、部分格式的梯度／誤差配對，以及 L2 的誤差分量抵消。但這些機制在不同層和 bit 不同，尚未證明哪一種修正能廣泛改善搜尋結果。

**既然知道少了一階，為什麼不加？**

一階在部分案例提供必要的方向資訊，但單獨一階會嚴重誤選。更重要的是，加入一階在跨層、新文章確認中沒有帶來改善，所以不能由 L27 成功就設成通用規則。

**最新 27／27 是否表示之前研究白做？**

它提供了對照邊界：原 BC 在這三層、FP32 背景的同 bit 排名良好；先前 L27 的 native 漏選仍成立。兩者測試條件不同，幫助把研究焦點縮到實際有影響的情境。

**是不是 calibration 太少，所以多加資料就好？**

L26 的直接校準 loss 選擇確實沒有轉移；但固定 token 預算改成多篇文章，只減輕部分傷害，沒有使選擇更穩定。不能說單純增加或換資料已是有效解法。

**是不是 Posit 的精度或量化器算錯？**

已有 LUT 與相關重現控制通過，也有 native 的正面局部案例。本週證據主要指向評分近似、分解與轉移條件；不能由分數高估直接認定 Posit 實作錯，也不能保證所有候選的跨後端行為完全一致。

**是否已到二階方法瓶頸？**

目前只證明若干局部二階 proxy／輸出端二次近似的限制，沒有證明所有二階方法都到上限。K_full 不是整個模型的完整 Hessian。

**為什麼 aggressive 點常看起來有改善？**

更大的量化損傷可能留下更多改善空間，但這是待驗證解釋。本週 OLMoE 同位置配對在 aggressive 未確認收益，Qwen E 在 aggressive 的改善也未過指定多重比較校正；不能把「aggressive 一定有效」當結論。

**現在正式 pipeline 有改嗎？**

本週沒有將這些研究變體納入正式預設；原 BC 與現有搜尋預設保留。離線時間、BOPs proxy 和部署 kernel latency 是不同指標，報告分開呈現。

## 附錄 F｜第二頁實際做過的更新版本

共同流程：FP32 static BC 建表 → 在固定資源點選 q0 → 用相同校準資料跑 q0 → 更新指定統計 → 在同一資源上限重新搜尋一次得到 q1 → 新文章評估。

| 版本 | 更新哪些統計 | 目的 |
|---|---|---|
| A：static baseline | 不刷新，沿用 FP32 統計 | 比較基準 |
| B：完整 refresh | 全部節點的 weight／activation sensitivity，以及 activation error | 先確認量化工作狀態下更新統計有無收益 |
| C：全部 sensitivity-only | 全部節點的 weight／activation sensitivity；誤差沿用 static | 省去候選 activation 誤差重算 |
| D4：≤4-bit sensitivity-only | q0 中 weight 或 activation ≤4-bit 的投影，更新其 weight／activation sensitivity | 減少需保留與彙整的梯度統計 |
| D5：≤5-bit sensitivity-only | 同上，擴至 ≤5-bit 的投影 | 檢驗 D4 在 knee 更新範圍較小的問題 |
| E：全節點 error-only | 只更新 activation 誤差的平均／變異；梯度統計沿用 static | 更新階段只需 forward，省去 backward |
| E5：≤5-bit error-only | 只更新 D5 同一組投影的 activation 誤差 | 進一步減少候選誤差計算 |
| W：weight sensitivity-only | 全節點只更新 weight sensitivity；activation 整項不動 | 分離 weight 項更新的作用 |

- 所有版本維持原 BC 公式、校準資料、ranges、量化器與 router 參數。依各資源點凍結的 q0 建立工作狀態，各變體不串接成多輪更新。
- 原始權重與候選量化器固定，所以候選 ΔW = Q_f(W)−W 不變；連完整 B 都重用 static weight error，不是重新量化 q0 的量化權重。
- Sensitivity 更新需要 forward／backward。Forward 使用 q0 自己的 dynamic route；backward 固定當次路由、QDQ 用 identity STE；沒有 optimizer 或參數訓練。
- D4／D5 只縮小統計收集範圍，反傳仍經整個模型；選中投影的所有候選格式都重算成本，不只重算四／五 bit 那一格。
- E／E5 只有更新階段不用 backward，最初建立 static BC 仍需梯度。
- 搜尋時全模型的 weight／activation 格式仍可重新分配；只更新 weight 統計，不代表 activation 格式固定。
- Knee 的 D4 目標 169／3051 個投影，D5 目標 1512／3051；aggressive D4 為 1161／3051。覆蓋差異已量到，但不能直接斷定它是效果消失的唯一原因。

來源：[C](../runs/olmoe_knee_all_sensitivity_20261022/report.md)、[D5](../runs/olmoe_knee_low5_sensitivity_20261022/report.md)、[E](../runs/olmoe_knee_error_only_20261022/report.md)、[E5](../runs/olmoe_knee_low5_error_only_20261022/report.md)、[W](../runs/olmoe_knee_weight_sensitivity_20261023/report.md)；B／D4 的來源見第二頁。
